# 第 4 章 超级管理员（`SUPER`）

## 4.1 角色定位与可见范围

平台超级管理员是系统的开户与治理角色，只做三件事：建机构、指定机构管理员、指定最终管理人。它不参与任何机构的研发业务。

| 项 | 说明 |
| --- | --- |
| 角色码 | `SUPER`，同时具备平台机构的管理员身份 |
| 菜单 | 仅“超级用户 > 机构/团队”（资源号 `5101`） |
| 数据范围 | 全部机构；但只能操作机构级配置，不能进入机构业务单据 |
| 不在范围内 | 研发管理组全部 25 项菜单、机构侧任何单据 |
| 典型工作 | 新客户开户、机构信息维护、管理员与最终管理人变更、机构删除 |

平台超级管理员与机构管理员是两个不同身份：前者管“有哪些机构”，后者管“这家机构有哪些人”。二者都叫“管理员”但权限不相交，只有平台超管能新建机构与指定最终管理人。

## 4.2 登录平台机构

### 4.2.1 适用角色与目的

仅平台超级管理员。目的：进入平台侧，取得机构/团队菜单。

### 4.2.2 入口

登录页。

### 4.2.3 操作步骤

1. 打开登录页。
2. 填写平台超管手机号。
3. 填写口令。
4. 填写图形验证码。
5. 在“登录机构”中选择平台机构（名称形如“平台超级用户（Mock）”）。
6. 点击【登录】。

### 4.2.4 结果与留痕

进入工作台，侧栏只有“超级用户”组的“机构/团队”。若侧栏出现“研发管理”组，说明选错了机构，须退出重登。

### 4.2.5 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 机构下拉中没有平台机构 | 手机号不属于平台机构 | 核对账号；平台机构只对应一个管理员手机号 |
| 登录后看到机构菜单 | 选了业务机构 | 退出后重选平台机构 |
| 提示账号锁定 | 连续失败 5 次 | 等待 15 分钟或由运维清除锁定 |

## 4.3 机构/团队列表与检索

### 4.3.1 入口

`超级用户 > 机构/团队`。

### 4.3.2 页面构成

| 区域 | 内容 |
| --- | --- |
| 检索区 | 团队名称关键词输入框 + 【查询】 |
| 列表区 | 机构 ID、登录名、团队名称、最终管理人、机构管理员、机构联系电话、机构状态、创建时间、操作 |
| 操作列 | 【设置最终管理人】【编辑信息】【变更机构管理员】【修改密码】【删除机构】 |

平台机构自身在列表中同样显示，但“变更机构管理员”“删除机构”两个按钮不出现，避免误删平台。

### 4.3.3 操作步骤

1. 在检索框输入团队名称关键词（支持部分匹配）。
2. 点击【查询】。
3. 通过“机构状态”确认机构是否在用；“最终管理人”列为空说明尚未设置。

### 4.3.4 结果与留痕

列表只读，不产生业务流水。机构状态、管理员、最终管理人的变化都在此页体现。

## 4.4 新建机构/团队（开户）

### 4.4.1 适用角色与目的

仅平台超级管理员。目的：为一家客户建立独立机构，并指定首个管理员。

### 4.4.2 入口

`超级用户 > 机构/团队 > 【添加机构/团队】`。

### 4.4.3 前置条件

- 已取得客户资料：登录名称、团队名称、管理员姓名与手机号、机构类型、预算模式。
- 管理员手机号未在任何机构登记为其他成员（一个手机号全局一个账号；如需在多家机构任职，用同一手机号即可，无需新建）。

### 4.4.4 操作步骤

1. 在机构列表页点击【添加机构/团队】，弹出“添加机构/团队”对话框。
2. 填写登录名称。
3. 填写团队名称。
4. 填写管理员姓名与管理员手机。
5. 按需设置用户数量限制、过期时间、存储空间。
6. 选择预算模式、机构状态、机构类型。
7. 点击【保存】。

### 4.4.5 字段说明

| 字段 | 必填 | 规则 | 示例 |
| --- | --- | --- | --- |
| 登录名称 | 是 | 2 至 6 个字符，机构维度唯一，用于登录与识别 | `Custom` |
| 团队名称 | 是 | 不超过 50 字，用于列表与页面显示 | `船舶智能化公司` |
| 管理员姓名 | 是 | 不超过 10 字 | `林总管` |
| 管理员手机 | 是 | 11 位手机号，作为该机构管理员的登录名 | `13900002000` |
| 用户数量限制 | 否 | 整数 1 至 100000 | `50` |
| 过期时间 | 否 | 日期；不选则不限制 | `2027-12-31` |
| 预算模式 | 否 | 下拉枚举，默认宽松 | 宽松 |
| 存储空间(GB) | 否 | 整数 1 至 1000000 | `100` |
| 机构状态 | 是 | 启用 / 停用，新建选启用 | 启用 |
| 机构类型 | 是 | 下拉枚举，按客户性质选择 | 产品型公司 |

### 4.4.6 结果与留痕

保存成功后：

1. 列表出现新机构，机构 ID 由系统生成，机构联系电话等于管理员手机号。
2. 系统自动为该机构建立成员记录、固定部门（产品中心、研发中心、系统工程部、测试部、质量部、法规部、物料部）与标准费率等基础数据。
3. 管理员初始口令为机构联系电话，首次登录须改口令。
4. “最终管理人”列暂为空，需按 4.8 设置。

### 4.4.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 登录名称不通过 | 少于 2 位或多于 6 位，或已被占用 | 换用未占用的名称 |
| 管理员手机不通过 | 非 11 位，或该号已是其他机构的最终管理人 | 核对号码；更换管理员或先处理原机构 |
| 保存后登录页看不到新机构 | 机构状态为停用 | 编辑信息改为启用 |
| 管理员无法登录 | 未用机构联系电话作为登录名 | 用“管理员手机”列的号码登录 |

## 4.5 编辑机构信息

### 4.5.1 适用角色与目的

仅平台超级管理员。目的：维护机构名称、状态、限额、过期时间与类型。

### 4.5.2 入口

`超级用户 > 机构/团队 > 机构行【编辑信息】`。

### 4.5.3 操作步骤

1. 点击【编辑信息】，打开机构信息对话框，字段与开户时一致，已带出当前值。
2. 修改需要变更的字段。
3. 点击【保存】。

### 4.5.4 字段与校验

字段规则同 4.4.5。三处需要特别注意：

| 字段 | 变更影响 |
| --- | --- |
| 机构状态 | 改为停用后该机构成员无法登录；在用机构慎改 |
| 用户数量限制 | 达到上限后机构管理员无法新增成员，需先调高 |
| 过期时间 | 到期后按停用处理；不选为不限制 |

### 4.5.5 结果与留痕

保存后立即生效。机构状态与限额的变化不影响已有业务数据，只影响登录与新增。

### 4.5.6 异常与处置

登录名称通常开户后不再变更，变更会影响该机构成员的登录识别，须先与客户确认。修改后成员若无法登录，核对是否误改了管理员手机号或机构状态。

## 4.6 变更机构管理员

### 4.6.1 适用角色与目的

仅平台超级管理员。目的：机构原管理员离职或换人时，把管理员身份移交本机构其他成员。

### 4.6.2 入口

`超级用户 > 机构/团队 > 机构行【变更机构管理员】`。

### 4.6.3 前置条件

- 目标成员已在该机构成员列表中（由现管理员在团队管理中建立）。
- 目标成员手机号未在其他机构担任管理员。

### 4.6.4 操作步骤

1. 点击【变更机构管理员】。
2. 在“新管理员”下拉中选择目标成员（按姓名检索）。
3. 点击【保存】。
4. 在确认框确认。

### 4.6.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 机构名称 | —— | 只读 |
| 新管理员 | 是 | 从本机构成员中选择 |

### 4.6.6 结果与留痕

机构联系电话改为新管理员手机号，新管理员登录后取得 `ADMIN`。原管理员失去 `ADMIN`，但仍是普通成员；若原管理员同时是最终管理人，需另行按 4.8 处理。

### 4.6.7 异常与处置

变更后新管理员看不到团队管理，说明未重新登录；原管理员仍有 `ADMIN`，说明其手机号仍是机构联系电话，需再次确认变更是否保存成功。

## 4.7 重置机构管理员口令

### 4.7.1 适用角色与目的

仅平台超级管理员。目的：机构管理员忘记口令且无法自助重置时恢复登录。

### 4.7.2 入口

`超级用户 > 机构/团队 > 机构行【修改密码】`。

### 4.7.3 操作步骤

1. 点击【修改密码】。
2. 输入新密码与重复新密码。
3. 点击【保存】。

### 4.7.4 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 登录名称 | —— | 只读 |
| 输入新密码 | 是 | 8 至 32 位，含字母与数字 |
| 重复新密码 | 是 | 与上一项一致 |

### 4.7.5 结果与留痕

新口令立即生效，该管理员此前全部会话被吊销；同时清除其登录失败计数与锁定。管理员用新口令登录后可直接进入，不再触发首次改口令流程。

### 4.7.6 异常与处置

重置后仍无法登录，先确认登录机构是否选对，再确认号码是否为机构联系电话。若该号在多家机构任职，口令是同一账号的口令，会同时影响其他机构。

## 4.8 设置最终管理人

### 4.8.1 适用角色与目的

仅平台超级管理员。目的：为机构指定唯一一位身份全权人，取得本机构 25 项菜单。

### 4.8.2 入口

`超级用户 > 机构/团队 > 机构行【设置最终管理人】`。

### 4.8.3 前置条件

目标成员已在该机构成员列表中且在职。

### 4.8.4 操作步骤

1. 点击【设置最终管理人】。
2. 在“最终管理人”下拉中选择成员。
3. 点击【保存】。
4. 在“更换最终管理人？”确认框中确认。

### 4.8.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 机构名称 | —— | 只读 |
| 最终管理人 | 是 | 本机构成员，单选，每机构一人 |

### 4.8.6 结果与留痕

1. 列表中“最终管理人”列显示该成员姓名。
2. 该成员重新登录后取得 `UltiMng`，菜单 25 项，并自动计入委员会、产品经理、项目经理、系统工程师四份资质名单，在资质设置中显示为“最终管理人（默认）”且不可移出。
3. 原最终管理人失去 `UltiMng`，并自动移出上述四份名单（除另被单独任命）。
4. 若管理员与最终管理人是同一人，其菜单仍为 25 项；改设他人后，管理员只剩 12 项。

### 4.8.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 设完菜单没变 | 未重新登录 | 退出重登 |
| 原最终管理人仍在四份名单 | 其被单独任命过 | 在团队管理资质设置中移出 |
| 无法设置 | 目标成员不在职或不属于该机构 | 先在团队管理恢复在职 |

## 4.9 删除机构

### 4.9.1 适用角色与目的

仅平台超级管理员。用于撤销试用机构或误建机构，属不可恢复操作。

### 4.9.2 入口

`超级用户 > 机构/团队 > 机构行【删除机构】`。平台机构不显示该按钮。

### 4.9.3 前置条件

- 已确认该机构无在用业务数据，或已完成数据备份。
- 已知该机构完整名称与超管口令。

### 4.9.4 操作步骤

1. 点击【删除机构】。
2. 阅读红色提示“删除后不可恢复”。
3. 手工输入完整机构名称。
4. 输入超管口令。
5. 确认删除。

### 4.9.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 机构名称 | 是 | 须与目标机构名称完全一致，用于防误删 |
| 超管密码 | 是 | 当前平台超管口令，服务端校验 |

### 4.9.6 结果与留痕

机构及其成员、业务数据不再可见，机构从登录页机构下拉中消失。删除动作本身不进入机构业务流水。

### 4.9.7 异常与处置

名称或口令不一致时不执行。误删无法通过页面恢复，只能由运维从备份恢复，因此删除前必须完成 4.9.3 的确认。

## 4.10 能力边界

超级管理员有四件“看起来该能做、实际不能做”的事，属设计限制：

| 不能做 | 原因 | 应由谁做 |
| --- | --- | --- |
| 进入机构研发管理菜单 | 平台超管不参与机构业务 | 机构管理员或岗位角色 |
| 在机构内新建成员、任命岗位 | 成员与任命归机构侧团队管理 | 机构管理员、最终管理人 |
| 修改机构菜单覆盖 | 覆盖只由最终管理人维护 | 最终管理人（见 6.7） |
| 代机构提交或审批单据 | 不产生业务权限，越权请求被拒 | 具备该操作的角色 |

## 4.11 开户交接清单

开户完成后，把以下 7 项交给机构管理员，交接即完成：

| 序 | 交接项 | 接受方动作 |
| --- | --- | --- |
| 1 | 机构登录名称与管理员手机号 | 用该手机号登录，选本机构 |
| 2 | 初始口令（= 机构联系电话） | 首次登录按提示改口令 |
| 3 | 最终管理人是谁 | 若为他人，需该人重登取得 25 项菜单 |
| 4 | 固定部门与标准费率已自动生成 | 在团队管理中核对，按需改负责人与费率 |
| 5 | 用户数量限制与过期时间 | 接近上限时提前申请调整 |
| 6 | 机构类型与预算模式 | 与实际管理口径不符时提交变更 |
| 7 | 报障方式与版本号位置 | 报障时提供页脚前后端版本 |

交接后平台超管的职责结束，后续人员与任命问题由机构侧处理。

## 4.12 常见问题

| 问题 | 处置 |
| --- | --- |
| 新机构成员登录时选不到机构 | 机构状态为停用，或登录名称刚改过；按 4.5 核对 |
| 机构管理员说没有团队管理 | 其手机号不等于机构联系电话；用【变更机构管理员】重设 |
| 一个机构能否有两个管理员 | 不能。管理员由联系电话唯一确定 |
| 最终管理人能否是管理员本人 | 可以；新建机构后建议先设为管理员本人，再按需改设 |
| 最终管理人离职怎么办 | 先设新最终管理人，再由新最终管理人在团队管理调整其成员状态 |
| 用户数量已达上限 | 调高“用户数量限制”后再由机构侧新增成员 |
| 误把机构停用 | 用【编辑信息】改回启用；停用期间成员无法登录但数据不丢 |
| 能否删除有业务数据的机构 | 技术上可以，但不建议；须先备份并确认客户已知情 |
