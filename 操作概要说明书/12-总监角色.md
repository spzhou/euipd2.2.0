# 第 12 章 总监角色（`PDGM` / `SYSGM`）

## 12.1 两个总监的定位与菜单

系统里有两个“总监”角色，都来自部门负责人，但能力差别很大：

| 项 | 产品总监 `PDGM` | 系统总监 `SYSGM` |
| --- | --- | --- |
| 来源 | 机构“产品中心（产品部）”负责人 | 机构“系统工程部”负责人 |
| 菜单数 | 14 | 10 |
| 与哪位角色菜单相同 | 产品经理 `PDM`（14 项完全一致） | 系统工程师 `SM`（9 项）+ 绩效/盘点 |
| 专有页签 | 预算汇总（`521801`） | 系统工程列表（`522101`） |
| 核心职责 | 产品线统筹、预算审阅、代位审批 | 系统工程部统筹、全部预立项的系统工程事项受理 |

一句话区分：**产品总监是“产品经理 + 预算汇总视角”，系统总监是“系统工程师 + 全员系统工程列表 + 部门绩效”**。

两者的菜单都随部门负责人变化即时生效：机构管理员在“团队管理 > 编辑部门”中调整负责人，被调整人重新登录后获得或失去该角色。

## 12.2 产品总监与产品经理的差异

菜单完全相同（14 项），差别只在两处：

| 维度 | `PDM` | `PDGM` |
| --- | --- | --- |
| 预算汇总页签（`521801`） | 不可见 | 可见 |
| 数据范围 | 本人负责的预立项与产品 | 本部门成员负责的预立项与产品（按部门过滤） |
| 质量管理 | 只看到本人为处理人的质量单 | 可看到本部门相关质量单 |
| 评审组长 | 缺省为预立项产品经理 | 仅在本人是该预立项产品经理时担任组长 |

产品总监不能“代所有产品经理审批特性”，审批权仍归属该预立项的产品经理。跨预立项代办须由机构管理员在预立项中调整产品经理，或由最终管理人代位。

## 12.3 预算汇总

### 12.3.1 适用角色与目的

仅产品总监（页签 `521801`）。目的：按产品线汇总各预立项与项目的预算编制与执行情况，用于部门预算审阅。

### 12.3.2 入口

`绩效/盘点 > 预算汇总`；或从产品管理进入后切换到“预算汇总”页签。

### 12.3.3 页面内容

| 区域 | 内容 |
| --- | --- |
| 汇总表 | 产品、预立项、项目、批准预算、已执行金额、执行率、剩余额度 |
| 分科目 | 材料费、工时费、其他费用三列展开 |
| 筛选 | 按产品、按项目状态、按时间区间 |
| 下钻 | 点击项目行进入该项目的预算明细（只读） |

### 12.3.4 操作要点

1. 预算汇总是只读视图，修改预算须在立项申请或预算调整流程中完成。
2. 执行率 = 已执行金额 ÷ 批准预算；物料执行额按领料金额减退料金额计算。
3. 项目评审通过后项目预算转 `COMPLETE`，此后行内不再变化。
4. 预立项阶段无预算，只有立项后才进入汇总。

### 12.3.5 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 新立项项目不在汇总 | 数据按机构与部门过滤 | 核对项目的产品经理是否属本部门 |
| 执行率与项目经理看到的不一致 | 项目经理看的是项目内视图，含未收口工单 | 以汇总视图为准做部门口径 |
| 想修改预算 | 汇总为只读 | 走预算调整流程或由最终管理人处理 |

## 12.4 产品总监的审批与代办范围

| 动作 | 产品总监能否做 | 说明 |
| --- | --- | --- |
| 新建预立项 | 能 | 与产品经理相同入口 |
| 预立项修订 | 能 | 限本人为该预立项产品经理 |
| 特性审批 | 能 | 限本人为该预立项产品经理 |
| 发起立项 | 能 | 限本人为该预立项产品经理 |
| 评审审结 | 能 | 限本人被指定为组长 |
| 产品发布 | 能 | 与产品经理相同入口 |
| 质量单处理 | 能 | 限本人为处理人 |
| 团队管理、职级、费率 | 不能 | 归机构管理员（5.4 至 5.6） |
| 直接立项、项目废弃 | 不能 | 归最终管理人（6.3、6.6） |

判断口径统一为：**先看菜单，再看数据归属，最后看该单据的“产品经理”字段是否等于本人**。

## 12.5 系统总监：系统工程列表

### 12.5.1 适用角色与目的

仅系统总监（页签 `522101`）。目的：在一个页面里看到本机构全部预立项的系统工程事项，掌握各预立项的审核、复核积压。

### 12.5.2 入口

`研发管理 > 系统工程 > 系统工程列表`。

### 12.5.3 页面内容

| 区域 | 内容 |
| --- | --- |
| 列表 | 预立项编号、名称、产品经理、系统工程师、开发版本、待处理事项数、创建时间 |
| 角标 | 有待受理事项时页签显示红点 |
| 行内操作 | 特性管理、系统工程（结构树）、任务管理、执行数据 |

### 12.5.4 与系统工程师的差别

| 维度 | `SM` | `SYSGM` |
| --- | --- | --- |
| 预立项列表 | 只看到本人任系统工程的预立项 | 看到本机构全部预立项 |
| 系统工程列表页签（`522101`） | 不可见 | 可见 |
| 审核与复核 | 只能审本人的 | 可查看全部，但**审核与复核仍须由该预立项的系统工程师办理** |
| 系统工程任务签发 | 能 | 能 |
| 绩效/盘点 | 无 | 有（管理驾驶舱、项目仪表盘、组织工作量） |

系统总监查看他人的系统工程事项时，具体办理按钮受单据“下一节点”限制，不会出现越权处理。

### 12.5.5 操作要点

1. 用“待处理事项数”排序，找出积压最多的预立项。
2. 积压属人的，通过线下沟通或调整预立项系统工程师解决，系统内不提供代审。
3. 部门人力的调配在“团队管理”由机构管理员完成，系统总监无该菜单。

## 12.6 总监的绩效与盘点视角

两个总监都有“绩效/盘点”菜单（`5200`），可见三个页签：

| 页签 | 内容 | 用途 |
| --- | --- | --- |
| 管理驾驶舱（`520002`） | 本月工时、交付、延期率、预算执行、质量成本的机构级汇总 | 部门月度复盘 |
| 项目仪表盘（`520003`） | 各项目完工率、逾期数、预算执行率、健康度 | 项目督办 |
| 组织工作量（`520004`） | 按部门与人员的工作量与负荷 | 人力调配 |

三个页签都是只读视图，详见 17.2。物料盘点页签（`520001`）不对总监开放，只属管理员与最终管理人。

## 12.7 部门负责人如何产生

两个总监角色都不是在“资质设置”里任命的，而是由部门负责人字段推导：

1. 机构管理员进入 `团队管理 > 组织关系`。
2. 在部门树中选择目标部门（产品中心、系统工程部、测试部、质量部、法规部、物料部、研发中心）。
3. 点击【编辑部门】，修改负责人。
4. 保存后，被设为负责人的成员重新登录即获得对应角色：
   - 产品中心 → `PDGM`
   - 系统工程部 → `SYSGM`
   - 测试部 → `TGM`
   - 质量部 → `QCGM`
   - 法规部 → `FGGM`
   - 物料部 → `MATM`
   - 研发中心 → 不产生角色（研发人员一律为 `STAFF`）

开户时七个固定部门已自动生成，负责人为开户的管理员。若某人同时是多个部门负责人，菜单取并集。

## 12.8 边界与交接

| 不做的事 | 由谁做 |
| --- | --- |
| 任命部门负责人、调整组织关系 | 机构管理员（5.9） |
| 代其他产品经理审批特性 | 产品经理本人，或最终管理人代位 |
| 代其他系统工程师给出审核意见 | 该系统工程师本人 |
| 项目废弃、直接立项、档案操作 | 最终管理人（6.3、6.6、6.9） |
| 修改预算金额 | 立项申请或预算调整流程 |

交接清单：

1. 产品总监每月用“预算汇总”核对执行率，异常项目转项目经理督办。
2. 系统总监每周用“系统工程列表”看待处理事项数，积压项目转对应系统工程师。
3. 部门内有人员变动，向机构管理员提出调整组织关系与负责人，不自行改名单。
4. 总监不承接具体工单时，不要让自己出现在单据的下一节点，否则流程会停在自己身上。

## 12.9 常见问题

| 问题 | 答复 |
| --- | --- |
| 为什么产品总监的菜单和产品经理一样多 | 两者菜单均为 14 项，产品总监多一个预算汇总页签 |
| 系统总监能不能替系统工程师审特性 | 不能，审核仍须由该预立项的系统工程师办理 |
| 为什么我在团队管理里找不到“产品总监”这个选项 | 总监不由资质设置任命，改部门负责人即可 |
| 研发中心负责人为什么没有角色 | 研发中心不生成角色，研发人员为 `STAFF` |
| 一个部门能不能有两个负责人 | 部门只有一个负责人字段 |
| 总监能不能看到全部机构的项目 | 不能，数据按机构隔离（`customer_id`） |
| 预算汇总能不能导出 | 页面提供导出，导出与当前筛选一致 |
