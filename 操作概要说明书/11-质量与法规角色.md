# 第 11 章 质量与法规角色（`QCGM` / `FGGM`）

## 11.1 两个角色的分工与菜单差异

质量与法规是两条线，岗位名称相近但能力不同：

| 项 | 质量总监 `QCGM` | 法规总监 `FGGM` |
| --- | --- | --- |
| 来源 | 机构“质量部”负责人 | 机构“法规部”负责人 |
| 菜单数 | 10 | 9 |
| 专有菜单 | 质量管理（`5213`） | 无 |
| 共有菜单 | 我的邮件、特性仓库、需求识别、执行管理、工期管理、质量反馈、档案管理、文档下载、绩效/盘点 | 同左（不含质量管理） |
| 核心职责 | 受理质量单、下发处理、审核结案、质量成本 | 档案与合规核查、以提出人身份发起质量反馈 |
| 页签 | 管理驾驶舱、项目仪表盘、组织工作量 | 同左 |

一句话区分：**质量总监管“质量单的处理”，法规总监管“档案与合规”**。法规总监没有质量管理菜单，因此不能接手质量单的处理，只能以提出人身份发起与复核。

## 11.2 质量总监：质量管理页构成

入口：`研发管理 > 质量管理`（资源号 `5213`，路由 `/customer/quality`）。

| 页签 | 内容 | 可见性 |
| --- | --- | --- |
| 质量问题列表 | 本人负责的质量单与状态 | 全部质量相关角色 |
| 质量处理总表 | 本机构全部质量单（跨项目、跨处理人） | 仅 `QCGM` |
| 质量处理 : 名称 | 单张质量单的处理页（下发、审核、结案） | 打开后出现 |
| 物料管理 / 费用管理 | 该质量单关联的领退料与费用 | 打开后出现 |
| 质量 : 项目名 | 该项目的质量成本统计 | 打开后出现 |
| 反馈 : 项目名 | 该项目的质量反馈清单 | 打开后出现 |
| 任务 : 项目名 | 该项目的质量任务（工单）清单 | 打开后出现 |

质量单的七个状态：

| 状态 | 含义 | 谁能推动 |
| --- | --- | --- |
| `SUBMIT` | 已提交，待受理 | 质量总监（下发处理工单） |
| `HANDLING` | 处理中 | 处理人提交分析 |
| `SAVE_ANALYSIS` | 分析已保存未提交 | 处理人 |
| `JOB_SUBMIT` | 分析已提交，待审核 | 质量总监（或产品经理） |
| `RECHECK` | 已结案，待提出人复核 | 提出人 |
| `REJECT` | 复核不通过 | 质量总监补充后再次提交 |
| `ARCHIVED` | 已归档 | 流程结束 |

## 11.3 质量问题列表与受理

### 11.3.1 适用角色与目的

质量总监（以及被指派为质量处理人的产品经理）。目的：查看待受理质量单，确认问题归属与严重度，决定是否受理并下发处理。

### 11.3.2 入口

`质量管理 > 质量问题列表`；跨项目查看用“质量处理总表”。

### 11.3.3 前置条件

质量单状态为 `SUBMIT`，由任何成员在“质量反馈”中提出并关联到具体项目/子项目。

### 11.3.4 操作步骤

1. 打开质量问题列表，按提交时间倒序查看。
2. 打开质量单，核对标题、问题描述（不少于 10 字）、关联项目与子项目。
3. 判断是否受理：属本机构产品问题则受理，否则退回提出人补充。
4. 受理即下发处理工单（见 11.4）。

### 11.3.5 结果与留痕

质量单转 `HANDLING`；被指派的处理人“执行管理”出现待办与角标；质量单过程记一条“下发处理”。

### 11.3.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 列表为空 | 无待受理质量单 | 正常；可在总表按状态筛选 |
| 质量单关联项目错误 | 提出人选错项目 | 退回提出人修改，不由质量总监改归属 |
| 同一问题重复提交 | 提出人重复提单 | 保留一张，其余在结案反馈中说明并标注重复 |

## 11.4 质量处理总表（`QCGM` 专属）

### 11.4.1 适用角色与目的

仅质量总监。目的：跨项目、跨处理人查看全部质量单的处理进度，用于周期复盘。

### 11.4.2 入口

`质量管理 > 质量处理总表`。

### 11.4.3 页面内容

| 区域 | 内容 |
| --- | --- |
| 列表 | 质量单编号、标题、关联项目/子项目、提出人、处理人、状态、提交时间、结案时间 |
| 筛选 | 按状态、项目、处理人、时间区间 |
| 行内操作 | 查看详情（只读）、催办（向处理人发出提醒） |

### 11.4.4 操作要点

1. 总表只用于查看与催办，不提供越权处理；处理仍须由该单的处理人在执行管理中完成。
2. 结案时间列可用于统计平均闭环时长。
3. 该页签只有 `QCGM` 能看到，`PDM` 在质量管理中只能看到自己的质量单。

## 11.5 下发质量处理工单与审核

### 11.5.1 适用角色与目的

质量总监。目的：把质量单转成可执行的处理工单，并在分析提交后审核。

### 11.5.2 入口

`质量管理 > 质量问题列表 > 质量单 > 【下发】`；审核在 `质量管理 > 质量单 > 【审核】`。

### 11.5.3 前置条件

- 质量单为 `SUBMIT`（下发）或 `JOB_SUBMIT`（审核）。
- 处理人为本机构在职成员（一般是研发工程师）。

### 11.5.4 操作步骤（下发）

1. 打开质量单，点击【下发】。
2. 选择处理人。
3. 填写任务说明（不少于 10 字，写清复现条件与期望结果）。
4. 填写计划工时与计划提交时间。
5. 提交。

### 11.5.5 操作步骤（审核）

1. 处理人提交分析后，质量单转 `JOB_SUBMIT`。
2. 打开质量单，核对分析五项：问题描述、本质分析、解决方案、输出指标、验证方法。
3. 选择【批准】或【驳回】。
4. 驳回必须填写原因；驳回后质量单回 `SAVE_ANALYSIS`，工单回 `HANDLING`。
5. 批准后填写评分与评价。

### 11.5.6 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 处理人 | 是 | 在职成员，受负荷校验 |
| 任务说明 | 是 | 不少于 10 字 |
| 计划工时 / 计划提交时间 | 是 | 数值与日期 |
| 审核意见 | 驳回必填 | 文本 |
| 评分 | 批准时填 | 记入绩效 |

### 11.5.7 结果与留痕

| 动作 | 状态 |
| --- | --- |
| 下发 | 质量单 `HANDLING`；工单 `HANDLING` |
| 处理人保存分析 | 质量单 `SAVE_ANALYSIS` |
| 处理人提交分析 | 质量单 `JOB_SUBMIT`；工单 `SUBMIT`，下一节点审核人 |
| 审核驳回 | 工单回 `HANDLING`；质量单回 `SAVE_ANALYSIS` |
| 审核批准 | 工单 `COMPLETED`；质量单等待结案反馈 |
| 提交结案反馈 | 质量单 `RECHECK`，回提出人复核 |

### 11.5.8 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 下发按钮灰显 | 质量单不是 `SUBMIT` | 核对状态 |
| 驳回后处理人没收到 | 工单未回 `HANDLING` | 核对工单状态 |
| 分析五项缺项 | 处理人未填全 | 驳回并写明缺项 |
| 结案后提出人不复核 | 提出人未处理 | 由总表催办，不能跳过复核直接归档 |

## 11.6 结案反馈与复核闭环

质量单的收口比缺陷反馈多一道复核，需记住顺序：

1. 处理人提交分析（`JOB_SUBMIT`）。
2. 审核批准并评分（工单 `COMPLETED`）。
3. 质量总监填写结案反馈并提交（质量单 `RECHECK`）。
4. 提出人在“质量反馈”页复核：
   - 通过 → `ARCHIVED`，闭环结束。
   - 不通过 → `REJECT`，重新出现在质量总监列表，需补充说明后再次提交结案反馈。

结案反馈要写清三件事：根因结论、已采取的纠正措施、预防再发的措施。复核不通过的常见原因是只写了“已修复”而未写预防措施。

## 11.7 质量成本统计

### 11.7.1 适用角色与目的

质量总监、产品经理。目的：按项目汇总质量相关的工时与物料消耗，评估质量成本。

### 11.7.2 入口

`质量管理 > 质量 : 项目名`（质量成本页签）。

### 11.7.3 页面内容

| 区域 | 内容 |
| --- | --- |
| 汇总 | 质量工单数量、质量工时合计、质量物料金额合计、质量成本合计 |
| 明细 | 按质量单列出的工时、物料与金额 |
| 对比 | 与项目预算中的质量科目对比 |

### 11.7.4 操作要点

1. 质量物料按领料金额减退料金额计入。
2. 质量工时按质量工单的核准工时计入，未评价的工单不计。
3. 数据随工单收口实时变化，不做快照。

## 11.8 质量反馈、缺陷反馈与质量单的区别

三张单据常被混用，务必分清：

| 单据 | 提出人 | 受理人 | 处理人 | 闭环标志 |
| --- | --- | --- | --- | --- |
| 质量单 | 任何人（`质量反馈` 菜单） | 质量总监或产品经理 | 研发工程师 | 提出人复核通过，`ARCHIVED` |
| 缺陷反馈 | 任何人（`执行管理 > 缺陷反馈`） | 子项目测试主管 | 研发工程师 | 提出人复核通过，`ARCHIVED` |
| 测试缺陷 | 测试工程师（在测试工单内） | 测试工程师本人 | 研发人员 | 测试工程师批准，缺陷 `COMPLETED` |

选择建议：

- 已交付客户、影响面跨子项目、需要留质量成本 → 质量单。
- 子项目内可复现的功能问题 → 缺陷反馈。
- 测试阶段发现的实现问题 → 测试缺陷。

## 11.9 质量领退料与处置复核

质量处理过程中如需要物料，走与研发相同的领退料流程：

| 环节 | 办理人 | 说明 |
| --- | --- | --- |
| 物料申请 | 质量工单处理人 | 单价自动取库存单价 |
| 领料审批 | 项目经理（该质量单关联子项目的项目经理） | 单价只读 |
| 发料确认 | 物料管理员 | 库存扣减 |
| 退料与收料 | 处理人发起、项目经理审批、物料管理员收料 | 库存回增 |
| 物料处置复核 | 产品经理 | 质量场景的处置复核人为产品经理，不是质量总监 |

质量总监在质量管理页的“物料管理 : 名称”页签可查看这些记录，但不具备审批权。

## 11.10 法规总监的职责与入口

法规总监 `FGGM` 没有质量管理菜单，其工作集中在档案与合规：

### 11.10.1 档案与文档

| 入口 | 用途 |
| --- | --- |
| `档案管理`（`5203`） | 查看各项目档案树的完整性，核对归档材料是否齐全 |
| `文档下载`（`5219`） | 按项目与文档分类下载受控文档 |
| `执行管理 > 档案申请` | 发起档案借阅、复制申请 |

档案的“档案操作”按钮（`520301`）只属最终管理人，法规总监只能查看与申请，不能直接归档或撤销归档。

### 11.10.2 合规核查

1. 在 `档案管理` 按项目检查归档完整性：特性六节正文、物料清单、测试与缺陷记录、评审记录、发布文件。
2. 发现缺项时，通过缺陷反馈或质量单提出（见 11.10.3），不走流程外沟通。
3. 对停产、版本变更等合规节点，核对产品管理中的版本与基线（只读）。

### 11.10.3 以提出人身份发起与复核

1. `质量反馈 > 新建质量单`，填写标题、问题描述、关联项目。
2. 提交后进入质量总监列表。
3. 质量总监提交结案反馈后，回到本人“质量反馈”页复核；不通过则填原因退回。

### 11.10.4 作为评审委员

若被列入委员会名单，法规总监可能被选为特性/子项目/项目评审委员，操作与系统工程师一致（见 8.11）：在 `执行管理 > 委员单 > 任务处理` 提交意见。

## 11.11 边界与交接

| 不做的事 | 由谁做 |
| --- | --- |
| 审批特性的技术内容 | 产品经理与系统工程师 |
| 下发研发工单、组织评审 | 项目经理 |
| 归档操作、项目废弃 | 最终管理人（6.6、6.9） |
| 修改团队、职级与费率 | 机构管理员 |
| 直接改质量单归属项目 | 提出人修改后重新提交 |
| 质量物料处置复核 | 产品经理 |

交接清单：

1. 下发质量处理前，先确认关联子项目与项目经理，避免领料审批找不到人。
2. 结案反馈写全根因、纠正、预防三段，减少复核退回。
3. 复核被退回后，先看提出人写的原因，补充说明再提交，不重复提交同一段文字。
4. 法规核查发现的档案缺项，用单据提出，留痕可追溯。

## 11.12 常见问题

| 问题 | 答复 |
| --- | --- |
| 为什么法规总监看不到质量管理 | `FGGM` 菜单 9 项，不含质量管理（`5213`） |
| 质量总监能不能代替产品经理处理质量单 | 能受理与审核，但物料处置复核仍归产品经理 |
| 质量单能不能不经过复核直接归档 | 不能，必须由提出人复核通过 |
| 质量成本里的工时为什么比我算的少 | 未评价的质量工单不计入 |
| 缺陷反馈能不能找质量总监处理 | 缺陷反馈归子项目测试主管受理，不是质量总监 |
| 质量单被驳回多次会有影响吗 | 只影响闭环时长统计，不影响绩效分，评分在审核环节给定 |
| 法规总监能否发布产品版本 | 不能，发布在产品管理或项目管理中由产品经理/项目经理操作 |
