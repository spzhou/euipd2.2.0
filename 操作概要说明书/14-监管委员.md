# 第 14 章 监管委员（`IPMT`）

## 14.1 定位与菜单

监管委员是研发投资的“审批与监督方”：管立项批准、管预算查看、管评审意见，并在项目评审时担任组长。委员不参与具体开发，也不管人与物料。

| 项 | 说明 |
| --- | --- |
| 角色码 | `IPMT`，来自委员会名单 |
| 菜单 | 13 项：我的邮件、预算管理、绩效/盘点、特性仓库、需求识别、立项管理、执行管理、工期管理、评审管理、绩效管理、质量反馈、档案管理、文档下载 |
| 不包含 | 预立项管理、系统工程、项目管理、研发管理、测试管理、物料、产品管理、质量管理、仓库、库存、团队管理、假日设置 |
| 核心入口 | 立项管理（审批）、评审管理（意见与列表）、预算管理（执行查看）、绩效管理（规则与统计） |
| 主要交接对象 | 产品经理（立项申请）、项目经理（执行与评审发起）、系统工程师（技术意见） |

委员不是“全局管理员”：看不见研发过程细节，也不能改任何执行数据。所有能力集中在审批、评审、查看三类。

## 14.2 立项审批（核心职责）

### 14.2.1 适用角色与目的

被指定为该项目监管委员的 `IPMT`。目的：审查立项申请的项目信息、团队、里程碑与预算，决定批准或驳回。批准后项目才真正成立。

### 14.2.2 入口

`研发管理 > 立项管理 > 待审批项目行【立项】`（审批动作）。

### 14.2.3 前置条件

- 项目状态为 `SETUP`（产品经理已提交）。
- 本人是该项目的监管委员（立项申请中指定的那一位）。

### 14.2.4 操作步骤

1. 进入立项管理，默认展示待审批项目。
2. 打开项目，逐项核对：
   - 项目名称、代码、分类、所属产品与主开发版本；
   - 监管委员、产品经理、项目经理、系统工程、测试主管与核心成员；
   - 里程碑：数量、日期、是否与发布时间匹配；
   - 特性清单：每项特性是否都已指定里程碑；
   - 预算表：材料费、工时费、其他费用的金额，特性预算之和是否与项目预算平衡；
   - 集成特性清单（CBB）：选用的 CBB 是否与本次开发范围相符。
3. 选择【批准】或【驳回】。
4. 驳回必须填写意见，写清需修改的具体项。
5. 提交。

### 14.2.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 审批结论 | 是 | 批准 / 驳回 |
| 审批意见 | 驳回必填 | 文本，记入项目过程与办理记录 |

### 14.2.6 结果与留痕

| 结论 | 结果 |
| --- | --- |
| 批准 | 项目与根子项转 `SETUPED`，根子项标识等于项目标识；全部特性转 `SETUPED`；预立项转 `CONVERTED`；生成项目基线（含各特性锁定版本与选用 CBB）；项目经理可开始建立子项目 |
| 驳回 | 项目回 `SETUP_EDIT`，交回产品经理修改后重新提交；项目过程保留驳回人与意见 |

批准后项目主开发版本锁定，特性版本进入基线，不能再通过预立项修订改动，只能走迭代。

### 14.2.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 列表里没有待审批项目 | 本人不是该项目的监管委员，或项目未提交 | 核对立项申请的监管委员字段 |
| 想改金额再批准 | 审批不提供改数 | 驳回并写明金额调整要求 |
| 批准后发现团队有误 | 已生成基线 | 由机构管理员调整组织关系，或按变更流程处理，不撤批 |
| 项目被反复驳回 | 预算或里程碑反复不合规 | 驳回意见写具体数值区间，减少往返 |

## 14.3 预算管理

### 14.3.1 适用角色与目的

监管委员（以及最终管理人）。目的：查看各项目的预算编制与执行情况，掌握投资执行进度。

### 14.3.2 入口

`研发管理 > 预算管理`（资源号 `5220`）。

### 14.3.3 页面内容

| 区域 | 内容 |
| --- | --- |
| 项目列表 | 项目代号、名称、批准预算、已执行、执行率、预算状态 |
| 分科目 | 材料费、工时费、其他费用三列 |
| 子项目明细 | 每个子项目的批准预算与执行额 |
| 下钻 | 点击项目进入明细，含领料与工时构成 |

### 14.3.4 计算口径

| 指标 | 口径 |
| --- | --- |
| 材料费执行额 | Σ（领料金额）− Σ（退料金额） |
| 工时费执行额 | Σ（已评价工单的结算绩效工时 × 标准工时费率） |
| 其他费用执行额 | Σ（已批准的费用申请金额） |
| 执行率 | 已执行金额 ÷ 批准预算 |
| 预算状态 | 编制中、执行中、已完成（项目评审通过后转 `COMPLETE`） |

### 14.3.5 操作要点

1. 预算管理是只读视图，委员不修改金额；如需调整，走预算调整流程或由产品经理重新提交立项。
2. 子项目预算是从根子项按科目划出的，各子项目之和不得超过根子项预算。
3. 执行额随领料、退料、工时评价、费用批准实时变化。
4. 质量成本单独在质量管理的“质量 : 项目名”页签查看，不并入项目预算执行额。

### 14.3.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 某项目不在列表 | 项目未批准或已归档 | 归档项目在档案管理中查 |
| 执行率超过 100% | 发生了超预算的领料或工时 | 由项目经理核对，走预算调整或收口 |
| 子项目之和大于项目预算 | 预算划分有误 | 由项目经理重新划分 |
| 数据与项目经理说的不一致 | 项目经理看的是项目内视图 | 以预算管理口径为准做汇报 |

## 14.4 作为评审委员

### 14.4.1 适用角色与目的

监管委员通常被指定为特性评审、子项目评审、主项目评审、里程碑评审、变更评审的委员（有时兼任组长）。目的：从投资与风险角度给出委员意见。

五类评审的组长不同：特性、子项目、变更为产品经理，主项目为监管委员，里程碑为主项目经理（见 9.16.8）。

### 14.4.2 入口

`执行管理 > 待办列表 > 委员单 > 任务处理`；意见汇总在 `评审管理 > 评审意见`。

### 14.4.3 操作步骤

1. 打开委员单。
2. 查看评审对象：特性清单与版本、物料清单、测试与缺陷记录、成本数据、交付件。
3. 填写评审意见，写清结论倾向与必须整改项。
4. 提交。

### 14.4.4 结果与留痕

委员单转 `SUBMIT`；组长在审结页可见全部委员意见。**委员未全部提交时，组长审结会被拒**（`REVIEW_COO_NOT_ALL_SUBMITTED`）。委员单提交后不可修改。

### 14.4.5 与组长审结的关系

| 角色 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| 委员 | 提交意见、查看评审对象 | 审结、改结论、代他人提交 |
| 组长 | 汇总意见、选择四种结论、决定是否发布为 CBB | 跳过委员提交 |

四种结论为：通过、有条件通过、增补、驳回（详见 7.6.5）。委员意见不直接决定结论，但会留档。

### 14.4.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 委员单不在待办 | 未被选为委员，或已提交 | 核对评审主单委员名单 |
| 想只表示“无意见” | 不支持弃权 | 填写明确意见（如“技术无异议，建议关注成本”） |
| 意见写错 | 已锁定 | 在评审通知或线下补充，不重开委员单 |

## 14.5 作为项目评审组长

### 14.5.1 适用角色与目的

项目评审的组长缺省为监管委员。目的：在主项目全部子项目完成后审结项目评审，使项目转完成、预算转完成。

### 14.5.2 入口

`执行管理 > 待办列表 > 项目评审主单 > 任务处理`。

### 14.5.3 前置条件

- 全部子项目为 `COMPLETE`，主项目为 `REVIEW_PRO`。
- 三名委员全部提交意见。

### 14.5.4 操作步骤

1. 打开项目评审主单。
2. 汇总委员意见，核对项目完工率、预算执行、缺陷闭环、物料清单。
3. 选择结论：通过 / 驳回。
4. 项目评审的审结页**没有发布选项**（发布为特性或集成级 CBB 只在特性评审与子项目评审提供）。
5. 提交。

### 14.5.5 结果与留痕

| 结论 | 结果 |
| --- | --- |
| 通过 | 项目与根子项转 `COMPLETE`；项目预算转 `COMPLETE`；评审通知派给项目经理，项目经理确认后主单 `COMPLETED` |
| 驳回 | 项目退回执行，按意见整改后由项目经理重新发起 |

### 14.5.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 审结被拒，提示委员未全部提交 | 委员缺席 | 由项目经理催办或重新发起评审 |
| 想发布 CBB | 项目评审无发布选项 | 特性与子项目评审阶段完成发布 |
| 审结后项目仍未归档 | 归档由产品经理或监管委员单独操作 | 按 6.9 或 9.17 执行 |

## 14.6 绩效管理与绩效规则

### 14.6.1 适用角色与目的

监管委员（以及机构管理员、最终管理人）。目的：按人员查看月度绩效工时与工时费，核对绩效规则执行结果。

### 14.6.2 入口

`研发管理 > 绩效管理`（资源号 `5216`，路由 `/customer/performance`）。

### 14.6.3 页面内容

| 页签 | 内容 |
| --- | --- |
| 当月绩效 | 本机构当月人员的绩效统计 |
| 往期绩效 | 按绩效周期查询历史 |
| 执行信息 | 工单级计入明细 |

列表列：工号、姓名、部门、绩效周期、交付总工时（标准）、延期率、延期绩效折扣、绩效工时费、负荷率、绩效评分。行内操作：【计入明细】【绩效统计】。

### 14.6.4 计算口径

页面标注的口径为：

- 工单结算绩效工时 = 工单绩效工时 ×（1 − 延期率 × 延期折扣）×（绩效基础 +（1 − 绩效基础））×（任务单评分 ÷ 10）
- 延期折扣 = 0.3；绩效基础 = 0.5
- 绩效工时费 = Σ（工单结算绩效工时 × 标准工时费率）

其中标准工时费率取团队管理中设置的团队标准费率（一个机构只有一个标准费率），个人员工费率按职级可另有取值。

### 14.6.5 操作步骤（核对）

1. 选择绩效周期与部门。
2. 按绩效工时费或延期率排序，找异常人员。
3. 点【计入明细】查看该人的工单级构成：工单号、特性、评分、绩效工时、结算绩效工时。
4. 点【绩效统计】查看该人按周期与项目的分布。
5. 发现评分或工时异常，回到对应工单核对（工单评价由项目经理完成）。

### 14.6.6 字段说明

| 字段 | 说明 |
| --- | --- |
| 交付总工时（标准） | 已评价工单的标准工时合计 |
| 延期率 | 延期工单占比或延期天数占比，按机构规则 |
| 延期绩效折扣 | 参与计算的折扣系数，默认 0.3 |
| 绩效工时费 | 结算绩效工时 × 标准费率 |
| 负荷率 | 已排工时 ÷ 可用工时 |
| 绩效评分 | 由工单评分汇总 |

### 14.6.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 某人工时费为 0 | 工单未评价 | 由项目经理完成评价 |
| 评分与服务端不一致 | 项目经理评价覆盖了测试评分 | 以最终评价为准 |
| 往期数据变了 | 历史工单被补评价 | 属正常，绩效按工单实时汇总 |
| 想改某人工时费 | 绩效管理为只读 | 修改须回到工单或费率设置 |

## 14.7 绩效/盘点视角

监管委员有“绩效/盘点”菜单（`5200`），可见三个页签：

| 页签 | 用途 |
| --- | --- |
| 管理驾驶舱（`520002`） | 机构级本月工时、交付、延期、预算执行与质量成本 |
| 项目仪表盘（`520003`） | 各项目完工率、逾期数、预算执行率、健康度 |
| 组织工作量（`520004`） | 按部门与人员的工作量与负荷 |

三个页签均为只读，详见 17.2；物料盘点页签（`520001`）不对委员开放。项目评审前用“项目仪表盘”核对结论支撑数据是最常见的用法。

## 14.8 边界与交接

| 不做的事 | 由谁做 |
| --- | --- |
| 新建预立项、发起立项 | 产品经理（7.2、7.5） |
| 建立子项目、下发工单 | 项目经理（9.3、9.8） |
| 特性审批、质量单处理 | 产品经理（7.4、7.8） |
| 直接立项、项目废弃、档案操作 | 最终管理人（6.3、6.6、6.9） |
| 组织与人员、职级与费率 | 机构管理员（5.4、5.6） |
| 入库、发料、收料 | 物料管理员（13.3、13.6、13.7） |

交接清单：

1. 收到立项待办后 2 个工作日内审批，避免阻塞项目启动。
2. 驳回意见写清具体数值与项，减少往返。
3. 被选为评审委员后，先看物料清单与测试记录，再看成本。
4. 项目评审结束后提醒项目经理确认评审通知，否则主单不会转完成。

## 14.9 常见问题

| 问题 | 答复 |
| --- | --- |
| 为什么我看不到预立项管理 | `IPMT` 不含预立项菜单，预立项由产品经理维护 |
| 能不能在立项审批时直接改预算 | 不能，只能驳回让产品经理改 |
| 委员能不能不提交意见 | 不能，不支持弃权，且未全部提交时组长不能审结 |
| 项目评审能不能发布 CBB | 不能，项目评审无发布选项 |
| 绩效工时费为什么按团队费率算 | 标准费率取团队管理中的标准费率，个人费率按职级 |
| 监管委员与最终管理人什么关系 | 角色不同；最终管理人可代办委员的审批动作（见 6.4） |
| 能不能查看研发工单明细 | 只在绩效管理的“计入明细”中只读查看，不进入研发管理 |
| 预算超支要不要报批 | 由项目经理核对后走预算调整，委员在预算管理查看结果 |
