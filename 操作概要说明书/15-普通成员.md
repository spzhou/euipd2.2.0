# 第 15 章 普通成员（`STAFF`）

## 15.1 定位与菜单

普通成员是没有被任命任何岗位角色的研发执行人员，也是全机构人数最多的角色。所有“被下发的工作”都落在这一角色的待办里。

| 项 | 说明 |
| --- | --- |
| 角色码 | `STAFF` |
| 菜单 | 8 项：我的邮件（`5301`）、特性仓库（`5205`）、需求识别（`5204`）、执行管理（`5202`）、工期管理（`5217`）、质量反馈（`5211`）、档案管理（`5203`）、文档下载（`5219`） |
| 不包含 | 团队管理、假日设置、预立项、系统工程、立项、项目管理、研发管理、测试管理、物料、评审、产品、绩效、质量、仓库、库存 |
| 核心入口 | 执行管理（全部工单）、需求识别（提需求）、工期管理（排期与工时） |
| 主要交接对象 | 项目经理（派工与评价）、系统工程师（审核）、测试主管（测试审核）、测试工程师（缺陷）、质量总监（质量单） |

普通成员虽然菜单只有 8 项，但**功能覆盖最广**：需求、特性、研发、测试、集成、缺陷、质量六类工单都在“执行管理”里办理。区别不在菜单，而在“下一节点是不是你”。

## 15.2 执行管理页构成

入口：`研发管理 > 执行管理`（资源号 `5202`，路由 `/customer/manhour`）。

| 页签 | 内容 | 用途 |
| --- | --- | --- |
| 任务列表 | 本人名下全部在办工单 | 接单与处理的主入口 |
| 我的文献 | 本人参与的全部文档与交付件 | 查看与下载 |
| 物料处理 | 本人经手的领料单、退料单与处置 | 发起退料、提交处置 |
| 费用处理 | 本人提交的费用申请 | 查看进度 |
| 缺陷反馈 | 缺陷反馈单的新建、查看与复核 | 提问题与复核结案 |
| 完工清单 | 本人已完成并评价的工单 | 核对工时与评分 |
| 增补特性建议 | 已注释下线，不再使用 | —— |

“任务列表”的列：任务号、任务名称、标准工时、执行人、任务类型、任务状态、项目/子项目名称、计划交付时间、剩余时间、里程碑时间、操作。剩余时间为负表示已逾期并标红。

任务类型决定打开哪张处理页：

| 集成任务 | 编 BOM、提交集成交付 | 15.9 |
| 缺陷工单 | 填处理说明并提交 | 15.10 |
| 缺陷处理（来自缺陷反馈） | 填分析五项 | 15.10 |
| 质量工单 | 填分析五项 | 15.11 |
| 增补任务 | 提交增补交付并自评 | 15.14 |

## 15.3 需求识别

### 15.3.1 适用角色与目的

任何成员。目的：把客户诉求、内部改进、缺陷引申转成正式需求，成为特性与项目的源头。

### 15.3.2 入口

`研发管理 > 需求识别`（资源号 `5204`）。

### 15.3.3 前置条件

- 目标预立项已建立且状态为 `DRAFT` 或 `ACTIVE`。
- 已想清需求边界与验收要点。

### 15.3.4 操作步骤

1. 进入需求识别，点击【新建需求】。
2. 选择所属预立项。
3. 填写需求名称与需求描述（不少于 10 字）。
4. 上传附件（可选）。
5. 保存草稿，核对后点【提交】。
6. 提交后可在列表中查看状态与下一节点。

### 15.3.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 所属预立项 | 是 | 本机构已有预立项 |
| 需求名称 | 是 | 可辨识，建议带前缀便于检索 |
| 需求描述 | 是 | 不少于 10 字 |
| 附件 | 否 | 图片、文档等；单个文件受大小限制 |

### 15.3.6 结果与留痕

| 动作 | 状态 |
| --- | --- |
| 保存 | `SAVED`（草稿），只有本人可见 |
| 提交 | `SUBMIT`，下一节点为预立项产品经理 |
| 产品经理下发 | `HANDLING`，产生需求工单 |
| 特性审批通过 | `COMPLETED` |

草稿可以删除；已提交的需求不能删除，只能由产品经理处理。

### 15.3.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提交被拒，提示描述过短 | 不足 10 字 | 补全描述 |
| 找不到预立项 | 预立项未建立或已关闭 | 找产品经理新建或确认 |
| 草稿在别人那里看不到 | 草稿只对本人可见 | 提交后再共享 |
| 提交后发现写错 | 已进流程 | 由产品经理在需求工单中驳回，或重新提一条并注明替代关系 |

## 15.4 任务列表与工时申报

### 15.4.1 适用角色与目的

任何成员。目的：查看自己被派了什么、什么时候到期，并在完成后申报工时与交付件。

### 15.4.2 入口

`执行管理 > 任务列表`。

### 15.4.3 操作步骤（接单与处理）

1. 打开任务列表，按“剩余时间”排序，先处理逾期的。
2. 点击任一行【任务处理】。
3. 按任务类型进入对应表单（见 15.2 表）。
4. 填写内容后保存或提交。

### 15.4.4 操作步骤（工时申报）

1. 在工单处理页找到“工时申报”区。
2. 按实际投入填写工时，可分行按日期记录。
3. 填写工作描述（做了什么、结果如何）。
4. 上传交付件（可选但强烈建议）。
5. 提交。

### 15.4.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 工作描述 | 是 | 文本，写清完成内容 |
| 工时申报 | 是 | 小时，累计不超过计划工时的合理倍数；超出时在描述中说明原因 |
| 交付件 | 建议 | 文档、代码包、图纸等 |
| 完成说明 | 否 | 遗留问题与后续建议 |

### 15.4.6 结果与留痕

工单转 `SUBMIT`，下一节点为审核人（项目经理、系统工程师或测试主管）；工时申报进入绩效计量，工单评价后被计入“完工清单”。

### 15.4.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 任务处理按钮提示到审核页办理 | 该工单只在业务页处理 | 按提示转到对应页 |
| 工时填多了保存不了 | 超出上限 | 与项目经理确认后调整计划工时 |
| 提交后被打回 | 交付件不全或描述不清 | 按意见补充后重新提交 |
| 完工清单里看不到 | 工单尚未评价 | 等审核与评价完成 |

## 15.5 特性定义

### 15.5.1 适用角色与目的

需求工单或特性定义工单的执行人。目的：把需求写成结构化特性，包括六节正文，供系统工程师审核与产品经理审批。

### 15.5.2 入口

`执行管理 > 任务列表 > 需求工单 > 任务处理`。

### 15.5.3 前置条件

需求工单的下一节点为本人（`HANDLING`）。

### 15.5.4 操作步骤

1. 打开需求工单。
2. 点击【新建特性】。
3. 填写特性名称。
4. 逐节填写六节正文：特性描述、接口定义、功能清单、性能指标、约束条件、验收标准。
5. 保存（特性 `SAVED`，下一节点仍为本人）。
6. 对同一需求可继续新建多条特性。
7. 全部特性填写完成后，在工单上点【提交】。

### 15.5.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 特性名称 | 是 | 可辨识，建议与需求呼应 |
| 特性描述 | 是 | 有正文，写清做什么、给谁用 |
| 接口定义 | 是 | 有正文，写清输入输出与外部依赖 |
| 功能清单 | 是 | 逐条列出功能点 |
| 性能指标 | 是 | 可测的量化指标 |
| 约束条件 | 否 | 技术、合规、环境限制 |
| 验收标准 | 是 | 可判定的通过条件 |

“特性描述”与“接口定义”两节必须写正文：特性发布为 CBB 时，这两节为空会被网关校验拒绝（`CBB_PUBLISH_GATE_FAILED`）。

### 15.5.6 结果与留痕

| 动作 | 状态 |
| --- | --- |
| 保存特性 | 特性 `SAVED` |
| 提交工单 | 特性 `SUBMIT`，下一节点为预立项系统工程师 |
| 系统工程师给出意见 | 工单转产品经理 |
| 产品经理批准 | 特性 `APPROVED`，生成特性版本号 |
| 产品经理驳回 | 特性回 `SAVED`，工单回 `HANDLING` 给本人 |

### 15.5.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提交按钮灰显 | 仍有特性为 `SAVED` 未完成 | 逐条补全 |
| 驳回后看不到意见 | 意见在特性过程页签 | 打开特性详情查看过程记录 |
| 想改已批准的特性 | 版本已锁定 | 走修订（由产品经理发起修订工单） |
| 六节写不全 | 无法提交 | 至少补齐必填三节（描述、接口、验收） |

## 15.6 分解工单

### 15.6.1 适用角色与目的

分解工单执行人。目的：把主特性拆成可独立开发与测试的子特性，交项目经理审批、系统工程师复核。

### 15.6.2 入口

`执行管理 > 任务列表 > 分解工单 > 任务处理`。

### 15.6.3 操作步骤

1. 打开分解工单，查看主特性内容。
2. 点击【新建子特性】。
3. 填写子特性名称与描述，按工时填写预算。
4. 重复新建，直到覆盖主特性的全部范围。
5. 点击【分解完成，提交任务】。

### 15.6.4 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 子特性名称 | 是 | 建议采用“主特性名 + 序号” |
| 子特性描述 | 是 | 写清本子特性范围与不做的事 |
| 预算工时 | 是 | 换算为子特性预算，合计不得超主特性预算 |
| 责任人 | 否 | 后续由项目经理在派工时确定 |

### 15.6.5 结果与留痕

子特性转 `SUBMIT`，下一节点为项目经理；主特性转 `DECOMPOSED`。项目经理逐条审批后子特性 `SETUP`，系统工程师复核通过后 `SETUPED`。

复核不通过时，全部子特性回 `SAVED`、分解工单回 `HANDLING`，由本人补充后重新提交（见 8.6.6）。

### 15.6.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 子特性预算合计超主特性 | 工时填多 | 下调或合并子特性 |
| 复核不通过 | 拆分不合理或描述缺失 | 按复核意见补全后重提 |
| 主特性一直 `DECOMPOSED` | 子特性未全部归档 | 属正常 |

## 15.7 研发工单

### 15.7.1 适用角色与目的

开发任务执行人。目的：按工单完成开发，申报工时，提交可验收的交付件。

### 15.7.2 入口

`执行管理 > 任务列表 > 开发任务 > 任务处理`。

### 15.7.3 前置条件

- 特性处于 `DEVELOPING`。
- 工单下一节点为本人。

### 15.7.4 操作步骤

1. 打开研发工单，读任务说明与计划时间。
2. 开发过程中如需物料，在工单内点【物料申请】（见 15.12）。
3. 完成后填写工作描述、工时申报。
4. 上传交付件。
5. 提交。

### 15.7.5 结果与留痕

工单转 `SUBMIT`，下一节点为子项目经理；项目经理审核后可签发测试工单或直接评价；评价完成后工单 `COMPLETED`，进入完工清单与绩效。

### 15.7.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提交后一直未审 | 项目经理未处理 | 通过线下或邮件提醒 |
| 被打回 | 交付件不合格 | 按意见补充后重提，工时可在重提时修订 |
| 需要追加物料 | 已提交 | 由项目经理驳回后再申请，或在下一次工单申请 |
| 工时被核减 | 与计划工时偏离大 | 在描述中补充原因，核减结果以审核为准 |

## 15.8 测试工单与缺陷下发

### 15.8.1 适用角色与目的

测试工单执行人（通常是测试工程师）。目的：按测试要点执行测试，发现缺陷直接下发，完成后提交测试交付与评分。

### 15.8.2 入口

`执行管理 > 任务列表 > 测试任务／特性测试 > 任务处理`。

### 15.8.3 操作步骤（测试执行与领料）

1. 打开测试工单，查看测试要点与计划时间。
2. 需要器材时点【物料申请】，走审批与发料（见 15.12）。
3. 逐项执行测试，记录结果。

### 15.8.4 操作步骤（下发缺陷）

1. 在测试工单中点【缺陷处理】。
2. 选择缺陷处理人（研发人员）。
3. 填写缺陷描述（现象、复现步骤、期望结果）。
4. 提交。缺陷工单 `HANDLING`，工时为 0，不占被测工单工时。
5. 处理人提交后回到本人：先【驳回】或【批准】；驳回回 `HANDLING`，批准后缺陷 `COMPLETED`。

### 15.8.5 操作步骤（提交测试交付）

1. 确认全部子缺陷已关闭（未关闭时提交会被拒）。
2. 填写工作描述与测试要点执行结果。
3. 对被测工单评分（0 至 10，示例中给 8 分）。
4. 写评价意见。
5. 提交。

### 15.8.6 结果与留痕

测试工单转 `SUBMIT`，下一节点为测试主管；测试主管批准后工单 `COMPLETED`，被测研发工单下一节点交回项目经理评价。**项目经理的评分会覆盖本人的评分**。

### 15.8.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提交被拒，提示子缺陷未关闭 | 有缺陷未闭环 | 催处理人提交后自己批准 |
| 缺陷工单工时显示 0 | 设计如此 | 不需填报工时 |
| 评分想改 | 已提交 | 由项目经理在评价环节调整 |
| 测试要点没写全 | 描述不规范 | 补写后重提 |

## 15.9 集成工单与 BOM 编辑

### 15.9.1 适用角色与目的

集成工单执行人。目的：把各研发工单的产出集成为完整特性，并形成特性物料清单（BOM）供评审与归档。

### 15.9.2 入口

`执行管理 > 任务列表 > 集成任务 > 任务处理`。

### 15.9.3 操作步骤

1. 打开集成工单。
2. 点【特性物料清单 BOM 编辑】。
3. 点【物料拣选】带入本项目已领用的物料。
4. 按实际装配调整行与数量。
5. 为每一行填写供应商与供货税率（必填）。
6. 提交物料清单（生成提交快照，清单 `SUBMIT`）。
7. 返回工单，上传集成交付件。
8. 提交集成工单。

### 15.9.4 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 物料编码／名称 | 是 | 来自拣选或手工添加 |
| 数量 | 是 | 正数 |
| 供应商 | 是 | 文本，BOM 行必填 |
| 供货税率 | 是 | 数值，BOM 行必填 |
| 备注 | 否 | 文本 |

物料拣选只列未取消、未驳回的领料单中的物料；已取消的领料单不会带入，手工添加时注意不要重复。

### 15.9.5 结果与留痕

清单 `SUBMIT`；集成工单 `SUBMIT`，下一节点子项目经理；项目经理评价后集成工单 `COMPLETED`，特性转 `DEV_COMPLETE`。评审通过后清单转 `LOCKED`，不可再改。

### 15.9.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| BOM 提交被拒 | 缺供应商或供货税率 | 补全行 |
| 拣选里没有某物料 | 该领料单已取消或驳回 | 手工添加并注明来源 |
| 清单提交后发现错 | 已生成快照 | 由项目经理协调在评审前撤回重提 |
| 特性评审要求清单已提交 | 前置条件 | 先提交清单再发起评审 |

## 15.10 缺陷处理与缺陷反馈

### 15.10.1 缺陷处理工单

适用：被指派处理测试缺陷或缺陷反馈的研发人员。

1. 入口：`执行管理 > 任务列表 > 缺陷工单／缺陷处理 > 任务处理`。
2. 测试缺陷：填写处理说明后提交，下一节点为测试工程师，由测试工程师批准或驳回。
3. 缺陷反馈：填写分析五项后提交——问题描述、本质分析、解决方案、输出指标、验证方法。
4. 提交后缺陷反馈转 `JOB_SUBMIT`，工单回测试主管审核。

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 处理说明 | 是 | 测试缺陷用 |
| 问题描述 | 是 | 缺陷反馈用，复现条件写清 |
| 本质分析 | 是 | 根因，不是现象 |
| 解决方案 | 是 | 改动点与影响面 |
| 输出指标 | 是 | 可验证的改善结果 |
| 验证方法 | 是 | 测试主管据此复核 |

### 15.10.2 缺陷反馈的提出与复核

任何成员都可以提缺陷反馈：

1. 入口：`执行管理 > 缺陷反馈`。
2. 点【新建】，填写标题、问题描述（不少于 10 字）、关联子项目、责成完成时间。
3. 提交后由该子项目测试主管转任务处理。
4. 测试主管提交结案反馈后，单据回到本人：点【复核】。
   - 通过 → `ARCHIVED`。
   - 不通过 → 填原因，单据 `REJECT`，回测试主管补充。

### 15.10.3 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 分析提交被驳回 | 缺本质分析或验证方法 | 按意见补充，不只写“已修复” |
| 缺陷反馈长期无人处理 | 未转任务 | 通过测试主管催办 |
| 复核不通过后无法再提 | 单据在 `REJECT` | 测试主管补充后重新提交结案 |

## 15.11 质量工单与质量反馈

### 15.11.1 质量工单

适用：被质量总监指派处理质量单的研发人员。

1. 入口：`执行管理 > 任务列表 > 质量工单 > 任务处理`。
2. 处理过程中如需物料，点【物料申请】（质量场景处置复核人为产品经理）。
3. 填写分析五项，先【保存】（质量单 `SAVE_ANALYSIS`），核对后【提交】（`JOB_SUBMIT`）。
4. 提交后下一节点为质量总监（或产品经理）审核。

### 15.11.2 质量反馈的提出与复核

1. 入口：`研发管理 > 质量反馈`（`5211`）。
2. 点【新建质量单】，填写标题、问题描述（不少于 10 字）、关联项目与子项目。
3. 保存后提交，进入质量总监列表。
4. 结案后在本页点【复核】：通过 → `ARCHIVED`；不通过 → 填原因，单据 `REJECT`。
5. 复核期间可用【查看进展】查看处理状态。

### 15.11.3 三张单据怎么选

| 场景 | 用哪张 |
| --- | --- |
| 已交付客户、影响跨子项目、要计入质量成本 | 质量单（质量反馈） |
| 子项目内可复现的功能问题 | 缺陷反馈 |
| 测试阶段发现的实现问题 | 测试工单内下发的缺陷 |

### 15.11.4 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 质量单分析被驳回多次 | 缺复现条件或预防措施 | 按意见逐项补，写清预防再发 |
| 复核不通过的按钮点不了 | 单据不在 `RECHECK` | 等质量总监重新提交结案 |
| 提交不了质量单 | 描述不足 10 字或未关联项目 | 补全 |

## 15.12 物料处理（领料、退料、处置）

### 15.12.1 适用角色与目的

任何需要物料的执行人。目的：在工单内申请物料、退还未用物料、对费用化物料提交处置。

### 15.12.2 入口

| 动作 | 入口 |
| --- | --- |
| 物料申请 | 研发／测试／集成／质量工单 > 【物料申请】 |
| 退料 | `执行管理 > 物料处理 > 领料单 > 【退料】` |
| 处置提交 | `执行管理 > 物料处理 > 领料单 > 【处置】` |

### 15.12.3 操作步骤（申请）

1. 在工单内点【物料申请】。
2. 选择仓库与物料，填写数量。
3. 单价自动取库存未税单价，不可修改。
4. 填写用途说明。
5. 提交。领料单 `APPLICATION`，下一节点为子项目经理。

### 15.12.4 操作步骤（退料）

1. 领料单必须是“已发料”状态，待发料状态下退料会被拒。
2. 在物料处理页找到该领料单，点【退料】。
3. 选择退回仓库与数量，填写原因。
4. 提交。退料单经项目经理批准、物料管理员收料确认后完成。

### 15.12.5 操作步骤（处置）

1. 领料单发料完成后，在物料处理页点【处置】。
2. 按费用化或资产化选择处置方式，填写处置说明。
3. 提交后由项目经理复核（质量场景为产品经理）。
4. 特性评审前必须完成全部费用化物料的处置，否则无法发起评审。

### 15.12.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提示 `MATERIAL_STOCK_SHORT` | 申请数量超库存 | 减少数量或让物料管理员补入库 |
| 待发料状态下不能退料 | 尚未出货 | 等发料完成 |
| 处置按钮不显示 | 领料未发料 | 等发料确认 |
| 申请单不在列表 | 不在本人经手范围 | 核对申请人 |

## 15.13 费用处理

### 15.13.1 适用角色与目的

任何成员。目的：申请研发过程中非物料的费用，并查看审批进度。

### 15.13.2 入口

`执行管理 > 费用处理`。

### 15.13.3 操作步骤

1. 点【新增费用申请】。
2. 选择关联项目或质量单。
3. 选择费用科目，填写金额、事由、发生日期。
4. 上传票据或附件。
5. 提交。

### 15.13.4 结果与留痕

申请单进入审批链（项目经理、最终管理人等，按流程配置），批准后占用相应预算科目，费用执行额进入预算执行率与绩效统计。

### 15.13.5 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提交被拒，提示预算不足 | 科目余额不足 | 减少金额或由产品经理申请预算调整 |
| 附件上传失败 | 文件超限或格式不支持 | 压缩或转 PDF |
| 被驳回 | 科目选错或事由不清 | 按意见修改后重提 |

## 15.14 增补任务、委员单与评审通知

### 15.14.1 增补任务

特性评审结论为“增补”时，派生增补任务给评审对象的项目经理，也可能是本人。

1. 入口：`执行管理 > 任务列表 > 增补任务 > 任务处理`。
2. 按增补要求补齐内容，上传交付件。
3. 提交后在 `研发管理 > 特性 > 任务审核` 中由本人【批准 & 评价】（增补任务允许自评）。
4. 增补任务 `COMPLETED` 后，评审主单回 `SUBMIT` 给组长，特性写回 `REVIEW`。

增补任务未完成时，组长无法再次审结（`REVIEW_TASK_UNFINISHED`）。

### 15.14.2 委员单

被选为评审委员时：

1. 入口：`执行管理 > 任务列表 > 委员单 > 任务处理`。
2. 查看评审对象与支撑材料。
3. 填写评审意见，提交。
4. 提交后不可修改；不支持弃权。

### 15.14.3 评审通知

1. 入口：`执行管理 > 任务列表 > 评审通知 > 任务处理`。
2. 核对评审结论与后续要求。
3. 点【确认】。通知单 `COMPLETED`，评审主单随之 `COMPLETED`。

不确认通知时主单不会收口，是常见的“评审已通过但流程没结束”的原因。

### 15.14.4 里程碑评审发起

只在本人是主项目经理时出现。系统在里程碑时间前 1 天自动派单，不由人工催办。

1. 入口：`执行管理 > 任务列表 > “发起评审:{里程碑名称}-里程碑评审” > 任务处理`。
2. 上半部任务信息只读；下半部填写“里程碑阶段评审申请表”：评审标题、任务描述、评审委员（穿梭框选人）、提交时间、附件。
3. 点【提交评审申请表】。发起单转 `COMPLETED`，系统生成里程碑评审主单并给每位委员派委员单；同一里程碑不能重复发起。
4. 委员提交意见后，本人在 `评审管理` 审结；里程碑评审没有结论选项，结论写入工作描述（详见 9.16）。

### 15.14.5 变更评审

特性修订分支需要纳入项目时，由产品经理发起变更评审（发起入口见 17.6.4）。被选为委员时与普通委员单一致：在 `执行管理 > 委员单` 填写意见；结论与特性评审相同，分通过、有条件通过、增补、驳回。

## 15.15 工期管理

### 15.15.1 适用角色与目的

任何成员。目的：按“执行中／已完成”与“开发／特性产品”四个维度查看自己的任务与工期，用于个人排期。

### 15.15.2 入口

`研发管理 > 工期管理`（资源号 `5217`，路由 `/customer/jobitem`）。

### 15.15.3 页面构成

| 页签 | 内容 |
| --- | --- |
| 开发执行中任务 | 本人研发类在办工单 |
| 开发已完成任务 | 本人研发类已完成工单 |
| 特性/产品执行中任务 | 本人特性与产品类在办工单 |
| 特性/产品已完成任务 | 对应的已完成工单 |

列：任务号、任务名称、标准工时、执行人、任务类型、任务状态、项目/子项目名称、计划交付时间、剩余时间（或完成时间）、里程碑时间。

### 15.15.4 操作要点

1. 剩余时间为负说明已逾期，优先处理。
2. 里程碑时间是承诺节点，逾期会影响项目健康度与个人延期绩效。
3. 该页只用于查看与跳转，不提供修改；工时申报仍在执行管理里做。

## 15.16 特性仓库、档案管理与文档下载

### 15.16.1 特性仓库

入口：`研发管理 > 特性仓库`（`5205`，路由 `/customer/module`）。用于查看已发布为 CBB 的复用组件。

1. 在 CBB 列表中按名称或来源特性检索。
2. 点【CBB 描述】查看概要、正文、定义、物料清单、开发档案五个页签。
3. 同源 CBB 会在同一分组下显示（同一特性多次发布时）。
4. 立项时选用的 CBB 只能在产品经理的立项申请中操作，本页只读。

### 15.16.2 档案管理

入口：`研发管理 > 档案管理`（`5203`）。按项目展开档案树，查看需求、特性、工单、评审、物料清单、交付件的归档情况。

档案的“档案操作”按钮（`520301`）只属最终管理人，普通成员只能查看与下载。

### 15.16.3 文档下载

入口：`研发管理 > 文档下载`（`5219`）。按项目与文档分类下载受控文档，下载受文档权限设置约束。

## 15.17 我的邮件

入口：`我的邮件 > 邮箱 / 写邮件`（资源号 `5301`）。

| 操作 | 说明 |
| --- | --- |
| 收件箱 | 查看收到的站内邮件，未读数每 60 秒刷新 |
| 写邮件 | 选择收件人（本机构成员）、填主题与正文、添加附件 |

## 15.18 边界与交接

| 不做的事 | 由谁做 |
| --- | --- |
| 新建预立项、发起立项 | 产品经理 |
| 派工、调整计划、评价工单 | 项目经理 |
| 审批特性、核定预算 | 产品经理 |
| 审核特性、复核分解 | 系统工程师 |
| 审核测试、处理缺陷反馈 | 测试主管 |
| 审批领退料、费用 | 项目经理 |
| 发料、收料、入库 | 物料管理员 |
| 处理质量单 | 质量总监或产品经理 |

交接清单：

1. 每天先看任务列表的逾期项，再看新增待办。
2. 提交前确认交付件已上传、工时已填，避免反复退回。
3. 需要物料在工单内先申请，等发料后再动工，不要先领后补。
4. 集成阶段先提交 BOM 再提交工单，否则评审会卡在物料清单。
5. 缺陷与质量单处理完，主动提醒审核人，缩短闭环时间。

## 15.19 常见问题

| 问题 | 答复 |
| --- | --- |
| 为什么我只有 8 项菜单 | `STAFF` 是基础角色，菜单固定 8 项，功能都在执行管理里 |
| 能不能看到别人的工单 | 只能看到自己为执行人或审核人的工单 |
| 工时填错了能不能改 | 提交前可改；提交后需项目经理驳回 |
| 能不能给自己下发任务 | 不能，派工权在项目经理 |
| 交付件支持哪些格式 | 文档、图片、压缩包等常用格式，单文件受系统限制 |
| 需求提交后能不能撤 | 不能，草稿可删，已提交须由产品经理驳回 |
| 为什么提交测试结果被拒 | 存在未关闭子缺陷，先闭环 |
| 为什么评审已通过但流程没结束 | 需有人在“评审通知”中确认 |
| 站内邮件能不能发给其他机构 | 不能，只在本机构成员间发送 |
