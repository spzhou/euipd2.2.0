# 第 17 章 专题操作

## 17.1 甘特图与计划下发

### 17.1.1 适用角色与目的

主项目经理、子项目经理（最终管理人与管理员可代办）。目的：把远期工作编成计划，由系统按计划开始时间自动下发，避免提前三个月给执行人堆任务。

### 17.1.2 两种下发方式

| 方式 | 入口 | 时间窗口 | 下发时点 | 下发后改期 |
| --- | --- | --- | --- | --- |
| 即时下发 | 研发管理、项目管理的下发任务对话框 | 计划提交时间不早于当日，不晚于当日起 3 个月 | 保存即下发 | 只能在“工期管理”改，仍受同一窗口约束 |
| 计划下发 | 子项目“计划”页签（甘特图） | 计划开始时间不早于次日；跨度不限 | 计划开始当日 8:30 由定时任务下发，也可“立即下发” | 只能在“工期管理”改，不受窗口约束 |

超过 3 个月的任务应编成计划，不要用即时下发。预立项域（需求、分解、修订、特性定义、迭代、复核）、产品域、各类评审、通知类工单不设下发窗口。

### 17.1.3 编制计划

1. 进入 `项目管理 > 项目行【项目管理】 > 计划页签`。
2. 在甘特图空白处新增计划行，填写：任务名称、任务描述、执行人、工时、计划开始时间、计划提交时间，可带附件。
3. 保存后计划状态为 `PLAN`（待下发）。
4. 需要表示先后关系时，在两条计划之间增加“完成—开始”依赖连线。

编制校验：

| 校验 | 规则 |
| --- | --- |
| 计划开始时间 | 不早于次日；当日开始的走即时下发 |
| 计划提交时间 | 不早于计划开始时间加“工时 ÷ 10”天（向下取整） |
| 子项目状态 | 已立项或执行中 |
| 超出子项目计划发布时间 | 提示但可保存 |
| 负荷 | 保存前按区间内日均负荷估算，超 10 小时提示，可继续保存 |

### 17.1.4 计划状态

| 状态 | 名称 | 进入条件 | 能否修改 |
| --- | --- | --- | --- |
| `PLAN` | 待下发 | 新建；或下发失败的计划修改后保存 | 能 |
| `ISSUED` | 已下发 | 定时下发或立即下发成功，生成工单 | 不能 |
| `FAILED` | 下发失败 | 定时下发时校验未通过 | 能，修正后再下发 |
| `CANCEL` | 已取消 | 所属子项目或项目废弃、关闭、归档 | 不能 |

删除只允许“待下发”与“下发失败”的计划，且为逻辑删除。

### 17.1.5 甘特图里有什么

| 行类型 | 起止 | 状态 | 可否编辑 |
| --- | --- | --- | --- |
| 子项目 | 立项时间至计划发布时间 | 进行中、逾期、已完成 | 否 |
| 特性 | 子项目立项时间至特性计划完成时间 | 按特性状态 | 否 |
| 里程碑 | 评审日 | 只读 | 否 |
| 工单 | 下发日至计划提交时间；已完成同时显示实际提交日 | 进行中、拒收待重下发、逾期、已完成 | 否 |
| 计划 | 计划开始时间至计划提交时间 | 待下发、下发失败 | 是 |

工单挂在所属特性下；无所属特性的挂在子项目下；项目级任务显示在根子项的甘特图中。工单状态归并规则：`HANDLING` 至 `APPROVED` 为进行中，`REFUSE` 为拒收待重下发，已过计划提交时间为逾期，`COMPLETED` 与 `ARCHIVED` 为已完成。

### 17.1.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 计划保存被拒 | 开始时间早于次日或提交时间早于下限 | 调整日期或改用即时下发 |
| 定时下发失败 | 执行人负荷超限或成员离职 | 修改计划后重新保存为 `PLAN`，或立即下发 |
| 甘特条拖不动 | 已下发工单在甘特图中只读 | 到“工期管理”改 |
| 甘特图与列表状态不一致 | 页面缓存 | 刷新或重开页签 |

## 17.2 工期调整

### 17.2.1 适用角色与目的

工单下发人、项目经理、产品经理（最终管理人与管理员可代办）。目的：在不重启流程的前提下调整已下发任务的计划提交时间或工时。

### 17.2.2 入口

`研发管理 > 工期管理`；或在甘特图中双击已下发工单，在只读详情里点【工期管理】。

### 17.2.3 操作步骤

1. 打开工期管理，定位工单。
2. 点【修改工期】，改计划提交时间；或点【修改工时】，改工时。
3. 保存。

### 17.2.4 规则

| 项 | 规则 |
| --- | --- |
| 下发时间 | 作为甘特条起点，不可修改 |
| 计划提交时间 | 即时下发与拒收重下发的工单受 3 个月窗口约束；计划下发生成的工单不受约束 |
| 已完成的工单 | 不允许改工期 |
| 修改留痕 | 记录修改人、时间与前后值 |

## 17.3 绩效与盘点

### 17.3.1 适用角色与目的

管理员、最终管理人、各业务总监、产品经理、项目经理、监管委员。目的：按人看工时与绩效，按项目看进度与预算，按部门看负荷，按仓看实物。

### 17.3.2 入口

`研发管理 > 绩效/盘点`（资源号 `5200`）。

### 17.3.3 四个页签

| 页签 | 资源号 | 谁可见 | 内容 |
| --- | --- | --- | --- |
| 物料盘点 | `520001` | 管理员、最终管理人 | 按仓按物料录入盘点数，提交后生成盘点调整流水 |
| 管理驾驶舱 | `520002` | 管理员、IPMT、PDGM、SYSGM、TM/TGM、QCGM、FGGM、UltiMng | 机构级本月工时、交付、延期率、预算执行、质量成本 |
| 项目仪表盘 | `520003` | `520002` 全部 + PDM、PJM | 各项目完工率、逾期数、预算执行率、健康度与判定原因 |
| 组织工作量 | `520004` | 同 `520002` | 按部门与人员的工作量与负荷 |

### 17.3.4 物料盘点

1. 选择仓库，点【新增盘点】。
2. 按物料录入实盘数量，系统显示账面数量与差异。
3. 提交后生成“盘点调整”流水，账面数量改为实盘数。
4. 盘点只调整数量，不调整单价。

### 17.3.5 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 看不到某页签 | 角色不在白名单 | 见附录 A |
| 盘点提交被拒 | 有物料未填实盘数 | 补全或删除未盘行 |
| 驾驶舱数据与绩效管理不一致 | 驾驶舱为机构汇总，绩效管理为人员明细 | 以各自口径使用，不做加减 |

## 17.4 版本与基线

### 17.4.1 五种常见版本

| 版本 | 承载对象 | 格式 | 何时变化 |
| --- | --- | --- | --- |
| 主开发版本 | 预立项、项目、子项目 | `01.00.0001`（两段两位 + 四段四位） | 预立项录入；迭代时按升级方式计算 |
| 特性编号 | 特性 | 主开发版本 + `-` + 四位，如 `01.00.0001-0002` | 首次审批为 `-0001`；修订或迭代合入后加一 |
| 内容版本 | 富文本正文 | `Vx.y` | 保存升小版；锁定升大版 |
| CBB 发布版本 | CBB | 发布时取承载对象版本 | 重新发布生成新记录 |
| 流程定义版本 | 流程定义 | 第 n 版 | 每次发布加一 |

主开发版本格式校验正则为 `^(0[1-9]|[1-9]\d)\.\d{2}\.\d{4}$`，即 `01.00.0001`、`02.03.0010` 这类写法。

### 17.4.2 基线

系统在三处生成基线，均为只读快照：

| 基线 | 生成时机 | 内容 | 查看入口 |
| --- | --- | --- | --- |
| 项目基线 | 立项批准 | 各特性锁定版本、选用的 CBB | 立项管理 > 项目“仪表盘” > 基线页签 |
| 特性基线 | 特性评审通过 | 特性正文、物料清单快照 | 特性详情 |
| 发布基线 | 产品发布 | 特性版本、CBB、物料清单、交付文件 | 产品管理 > 产品版本 > 基线 |

基线一旦生成不可修改；需要变更只能走迭代重新立项。

### 17.4.3 版本锁定的三个时点

1. 特性审批通过后，主开发版本不可再改（`DEV_VERSION_LOCKED`）。
2. 立项批准后，特性版本进入项目基线，内容线锁定为 `ACTIVE`。
3. 评审通过后，物料清单转 `LOCKED`。

## 17.5 CBB 复用、停用、废弃与重新发布

### 17.5.1 生命周期

| 状态 | 页面名称 | 可被新引用 | 已有引用 | 可逆 |
| --- | --- | --- | --- | --- |
| `ARCHIVED` | 已发布 | 是 | 不变 | —— |
| `DISABLED` | 已停用 | 否 | 不变，技术文档仍可看 | 可启用 |
| `DISCARD` | 已废弃 | 否 | 不变，技术文档仍可看 | 不可逆 |

停用用于暂时退出候选，废弃用于确认不再推荐（已有替代品或技术淘汰）。

### 17.5.2 复用

1. 立项申请时在“集成特性清单”中选用 CBB，候选只列已发布状态的 CBB。
2. 选用后在项目基线与发布基线中固化。
3. 在 `特性仓库 > CBB 描述 > 技术文档` 查看概要、正文、定义、物料清单、开发档案。
4. 在 CBB 详情查看“被引用反查”，确认哪些项目在用。

### 17.5.3 停用与废弃

1. 进入 `特性仓库`，找到目标 CBB。
2. 点【停用】或【废弃】，填写原因。
3. 停用可再点【启用】恢复；废弃无恢复入口。

停用与废弃都不影响已有引用项目的基线；只影响后续立项能否选用。

### 17.5.4 重新发布

对已发布 CBB 的承载特性做迭代后再次评审发布，会生成一个新的、独立的 CBB 记录（不是覆盖）。同一特性多次发布时在列表中形成“同源分组”。

### 17.5.5 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 立项时选不到某 CBB | 已停用或已废弃 | 由最终管理人或产品经理确认后启用 |
| 停用后已有项目报错 | 不应该发生 | 已有引用不受影响，如出现按缺陷反馈处理 |
| 同一特性出现两个 CBB | 迭代后重新发布 | 属正常，按发布版本区分 |

## 17.6 特性修订、迭代与增补

### 17.6.1 三种变更方式的选择

| 方式 | 适用阶段 | 版本变化 | 入口 |
| --- | --- | --- | --- |
| 修订 | 预立项阶段（立项前） | 特性编号加一 | 预立项管理 > 特性 > 修订 |
| 迭代 | 项目发布后 | 新主开发版本下重建记录 | 产品管理 > 项目“特性管理” > 版本升级 |
| 增补 | 评审结论为增补时 | 版本不变，补内容 | 评审审结时自动派生增补任务 |

立项后的特性不允许“终止”，也不允许直接修订，只能走迭代。

### 17.6.2 增补

1. 组长审结选“增补”，填增补要求与计划完成时间。
2. 系统派生增补任务给评审对象的项目经理。
3. 项目经理提交增补交付后自评（批准 & 评价）。
4. 主单回 `SUBMIT`，特性写回 `REVIEW`，组长再审。

增补任务未完成时不能再次审结（`REVIEW_TASK_UNFINISHED`）。

### 17.6.3 有条件通过

组长审结选“有条件通过”时，特性直接 `ARCHIVED`，同时派收尾任务按条件跟进。与增补的区别是：有条件通过不再回到评审，增补必须再审。

### 17.6.4 修订分支与变更评审

特性正文的版本面板（`特性 > 起草／修订页 > 版本管理`）按主开发版本线列出主线版本与各分支。分支分三类：修改分支（无归属）、修订分支（已确认生成新特性版本）、纳入分支（把新版本纳入已有项目）。分支状态：`OPEN` 编辑中、`REVIEWING` 变更评审中、`APPROVED` 待合入、`MERGED` 已合入、`ABANDONED` 已放弃、`OUTDATED` 已过期。

**发起纳入项目变更评审**

1. 点击主开发版本行右侧【纳入项目】。显示条件：编辑线 `ACTIVE`、最新内容版本高于项目锁定版本、且没有处理中的纳入分支。
2. 系统创建纳入分支并弹出变更评审单。
3. 填写评审标题（5 至 50 字）、任务描述（10 至 500 字）、截至时间、评审委员（至少 1 人）。
4. 提交后分支转 `REVIEWING`，评审管理新增一条类型为“变更评审”的记录。

已存在纳入分支但未发起评审时，在该分支行点【发起变更评审】补发。

**评审与合入**

| 分支状态 | 可做的动作 |
| --- | --- |
| `OPEN` 编辑中 | 继续改正文；【放弃】、【更新基线】；纳入分支可【发起变更评审】 |
| `REVIEWING` 变更评审中 | 等待审结，不能改正文 |
| `APPROVED` 待合入 | 【合入确认】，按提示处理章节冲突 |
| `MERGED` 已合入 | 只读，正文进入项目基线 |
| `ABANDONED` | 只读，不可再合入 |
| `OUTDATED` | 基线已前进且分支未跟进，可【更新基线】或【放弃】 |

合入确认后刷新项目、工单与角标，分支最新版本成为项目锁定版本。**修订分支不走合入确认**，其确认仍在特性审批页由产品经理完成。

**分支操作**

| 操作 | 入口 | 说明 |
| --- | --- | --- |
| 新建修改分支 | 版本面板底部【新建修改分支】 | 从当前基线派生，状态 `OPEN` |
| 更新基线 | 分支行【更新基线】 | 基线前进后把分支重放到最新基线；章节有交集时逐节选定保留内容 |
| 放弃 | 分支行【放弃】 | 转 `ABANDONED` |
| 对比 | 勾选两个版本后【对比所选两个版本】 | 逐章节对照 |
| 关系图 | 版本面板底部【以关系图查看】 | 查看派生与合入谱系 |

版本行的“类型”分派生起点、编制版本、工作版本、锁定版本；编辑线状态分 `DRAFTING` 编制中、`ACTIVE` 已锁定、`CLOSED` 已关闭，只有 `ACTIVE` 的编辑线可以纳入项目。

## 17.7 工作移交

### 17.7.1 适用角色与目的

机构管理员。目的：人员离职、调岗或长期不在岗时，把其名下的在办事项整体转给接收人，避免流程停在无人处理的节点。

### 17.7.2 入口

`团队管理 > 工作移交`。

### 17.7.3 操作步骤

1. 选择移交人（原责任人）与接收人。
2. 点【预览】，查看将移交的事项类别与数量：岗位与组织、项目与产品、特性与需求、工单与甘特计划、质量与缺陷、费用与领退料、预算、档案与文件、文档修改分支与编辑锁、流程待办。
3. 核对数量与预期一致后确认移交。
4. 在“历次移交记录”中查看本次结果。

### 17.7.4 移交范围与边界

| 会移交 | 不移交 |
| --- | --- |
| 未完成的工单、待办与流程实例 | 已办结的终态记录 |
| 项目、子项目、特性、需求的责任人 | 办理记录与过程表（历史留痕） |
| 甘特计划与待下发任务 | 预算执行流水、绩效、库存流水 |
| 质量单、缺陷反馈的处理人 | 文件上传人等归属字段 |
| 待审批的费用与领退料 | 富文本草稿与置顶标记 |
| 档案与文件的可办事项 | 流程引擎历史表 |

### 17.7.5 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 预览数量为 0 | 该人无在办事项 | 属正常 |
| 移交后接收人看不到 | 未重新登录 | 重登 |
| 想撤销移交 | 不支持撤销 | 反向再做一次移交 |

## 17.8 假日设置与工作日历

### 17.8.1 适用角色与目的

机构管理员、最终管理人。目的：维护本机构的放假与调休日期，使计划提交时间、工期计算与延期判定符合实际工作日。

### 17.8.2 入口

`研发管理 > 假日设置`（资源号 `5228`）。

### 17.8.3 操作步骤

1. 选择日期区间。
2. 对区间内的日期标记【放假】或【上班】（调休）。
3. 填写备注（不超过 30 字）。
4. 保存。日历与列表同步更新。
5. 需要撤销时点【恢复默认】，回到周一至周五工作、周末休息的默认规则。

### 17.8.4 影响范围

| 受影响 | 不受影响 |
| --- | --- |
| 计划提交时间的下限推算 | 已下发的计划提交时间（不回溯改写） |
| 延期率与延期绩效折扣 | 工时申报数值 |
| 剩余时间与逾期标记 | 库存、预算 |

## 17.9 批量导入

系统提供三类导入，模板均在页面内下载：

| 导入对象 | 入口 | 关键规则 |
| --- | --- | --- |
| 员工 | `团队管理 > 员工列表 > 批量导入` | 手机号唯一；部门需在导入后于组织关系中归入 |
| 物料入库 | `库存管理 > 下载模板 / Excel 导入` | 整批原子性，任一行错则整批不入库并提示行号 |
| 需求 | `需求识别 > 导入`（若页面提供） | 逐行校验描述字数与预立项归属 |

导入失败时按提示的行号与原因修正后重新导入，不要分批试探，避免部分成功造成数据不一致。

## 17.10 富文本、导入导出与在线查看

### 17.10.1 富文本编辑

特性正文、评审意见、CBB 描述均为富文本，支持标题、列表、表格、图片与附件。保存即生成内容版本 `Vx.y`；文档被锁定时升为 `Vx.0` 并只读。版本面板、修改／修订／纳入分支与变更评审见 17.6.4。

### 17.10.2 导出

| 对象 | 格式 | 入口 |
| --- | --- | --- |
| 列表数据 | Excel | 列表页【导出】 |
| 特性技术文档 | Word | 技术文档页【导出】 |
| 评审材料汇总 | Word | 评审详情【汇总导出】 |

导出内容与当前筛选一致；版式由渲染模板决定。

### 17.10.3 在线查看

Office 文档支持在线查看，依赖 Collabora 服务。服务未启动时在线查看不可用，导出 Word 仍可用；此时相关检查应记为未测，不作为缺陷。

## 17.11 档案申请与文档权限

### 17.11.1 档案申请

1. 入口：`执行管理 > 档案申请`。
2. 选择要借阅或复制的档案范围，填写用途与期限。
3. 提交后由档案管理方审批。
4. 批准后可在 `档案管理` 或 `文档下载` 中查看授权范围内的文件。

### 17.11.2 文档权限

文档的可见与下载受三类因素约束：所属项目/子项目的成员关系、文档密级设置、档案申请授权。超出范围时页面不显示文件或下载被拒。

## 17.12 费用申请

1. 入口：`执行管理 > 费用处理`。
2. 新增费用申请：关联项目或质量单、选科目、填金额与事由、上传票据。
3. 提交后进入审批链（项目经理 → 最终管理人，按流程配置）。
4. 批准后占用预算科目；驳回后回本人修改重提。

费用不生成库存流水，只影响预算执行额与绩效统计。

## 17.13 内部邮件

入口：`我的邮件 > 邮箱 / 写邮件`（`5301`，全员可用）。

| 操作 | 要点 |
| --- | --- |
| 写信 | 收件人限本机构成员，可多选；支持附件 |
| 收件箱 | 未读数每 60 秒刷新，侧栏角标同步 |
| 回复 / 转发 | 保留原邮件引用 |
| 删除 | 移入已删除 |

邮件是沟通工具，不改变任何业务单据状态，也不能作为审批留痕。

## 17.14 流程配置与权限配置

### 17.14.1 现状

这两个菜单只属最终管理人（`5226`、`5227`），且**侧栏入口已注释下线**。需要时由实施人员直接访问地址：

| 功能 | 地址 |
| --- | --- |
| 权限配置（机构菜单覆盖） | `/system/tenant-ui-policy` |
| 流程配置 | `/customer/flow` |

### 17.14.2 流程配置的三个页签

| 页签 | 用途 |
| --- | --- |
| 流程图 | 查看全部既有流程的图形与节点说明 |
| 设计 | 绘制本机构流程定义，保存草稿与发布版本 |
| 进度 | 按业务主键查看某张单据当前走到哪个节点 |

发布后新启动的实例按新版本流转，已启动实例保持原路径。节点审批人为空会导致发布后卡住。

### 17.14.3 权限配置的边界

| 规则 | 说明 |
| --- | --- |
| 可调整对象 | 本机构其他角色；管理员列与最终管理人列为锁定列 |
| 固定授予 | 团队管理、假日设置只属管理员与最终管理人；仓库、库存只属最终管理人与物料管理员 |
| 平台模板差异 | 平台新增资源不自动加入已调整角色，需【并入新增资源】后保存 |
| 恢复 | 每列可【恢复本列默认】，也可【全部恢复默认】 |

机构覆盖对本机构的管理员与最终管理人本身无效。

## 17.15 项目废弃、关闭与停产

| 动作 | 谁做 | 效果 | 是否可逆 |
| --- | --- | --- | --- |
| 预立项关闭 | 产品经理 | 不能再发起立项 | 新建预立项代替 |
| 项目废弃 | 最终管理人 | 项目转关闭，未结束特性写废弃、未结束工单写取消，预算停止执行 | 不可逆 |
| 项目归档 | 产品经理、监管委员 | 全部数据只读 | 不可逆 |
| 产品停产 | 产品经理 | 该发布版本停止维护，保留台账 | 可再启用（按产品管理页面） |

停产针对产品版本，不针对项目；停产产品仍可在特性仓库与档案中查询。

## 17.16 专题操作常见问题

| 问题 | 答复 |
| --- | --- |
| 计划为什么没按时下发 | 定时任务在计划开始当日 8:30 执行，校验未通过会转 `FAILED` 并通知创建人 |
| 甘特图能不能改已下发工单的日期 | 不能，只能在工期管理改 |
| 主开发版本能不能写成 `1.5` | 会按兼容规则规范为 `01.50.0000`，建议一律四段写法 |
| 基线能不能改 | 不能，只能迭代后重新生成 |
| 停用的 CBB 已有项目受影响吗 | 不影响，已有引用与基线不变 |
| 移交会不会把历史办理记录也转走 | 不会，终态记录与过程表保留原责任人 |
| 假日设置会影响已下发的计划吗 | 不会回溯，只影响新的推算 |
| 富文本导出的 Word 版式不对 | 与渲染模板有关，不改业务数据 |
| 流程配置改了为什么在办单据不变 | 已启动实例走原流程版本 |
