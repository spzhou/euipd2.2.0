# 第 9 章 项目经理（`PJM`）

## 9.1 定位与菜单

项目经理是研发主线的“执行组织者”：把已立项的特性拆到子项目、分给人、盯进度、管物料、组织五类评审（特性、子项目、主项目、里程碑、变更），最后把项目和子项目收口。

| 项 | 说明 |
| --- | --- |
| 角色码 | `PJM`，来自项目经理名单 |
| 菜单 | 14 项：8 项通用 + 绩效/盘点、预立项管理、项目管理、研发管理、物料管理、评审管理 |
| 页签 | 绩效/盘点中可见管理驾驶舱、项目仪表盘、组织工作量；不可见物料盘点 |
| 不包含 | 立项管理、系统工程、测试管理、产品管理、质量管理、仓库、库存、团队管理 |
| 主要交接对象 | 产品经理（立项与评审组长）、系统工程师（复核）、测试主管（测试）、执行人（工单）、物料管理员（发料收料） |

### 9.1.1 两类项目经理

同一个 `PJM` 角色在不同层级上权限不同，判定依据是项目上的“项目经理”字段：

| 类型 | 判定 | 能做 |
| --- | --- | --- |
| 主项目经理 | 主项目（根子项）上的项目经理 | 新建子项目、分配特性、主项目度量与评审、项目归档、发布产品版本 |
| 子项目经理 | 子项目上的项目经理 | 本子项目的启动研发、分解、下发任务、物料审批、特性评审发起、子项目评审发起 |

越界会被拒绝：子项目经理对不属于自己子项目的特性点【启动研发】，返回 `NO_PERMISSION`；主项目经理对子项目内的任务只能查看，不能下发。

### 9.1.2 主项目的“根子项”

项目批准时系统同时生成一个与项目同标识的根子项，主项目的特性先挂在根子项下。因此主项目经理在“项目管理”里看到的是两层：根子项（项目本身）与各子项目。

## 9.2 项目管理页的构成

入口：`研发管理 > 项目管理`。

### 9.2.1 列表列

| 列 | 说明 |
| --- | --- |
| 项目代号 / 项目名称 | 项目代码与名称 |
| 产品经理 / 项目经理 / 测试主管 / 系统工程师 / 监管委员 | 立项时指定的五个关键人 |
| 研发类型 | 特性开发项目、直接立项项目等 |
| 创建时间 / 发布时间 | 发布时间为空表示尚未发布 |
| 完工率 / 逾期数 | 完工率按已完成工单占比；逾期数为已超期未完成工单数，大于 0 时标红 |
| 预算执行率 | 已执行金额 ÷ 批准预算 |
| 健康度 | 正常／关注／预警，鼠标悬停显示判定原因（逾期、预算、进度偏差） |
| 状态 | 立项待审批、已立项、进行中、子项目评审、项目评审、已完成、已关闭、已归档 |
| 操作 | 见 9.2.2 |

### 9.2.2 行内操作按钮

| 按钮 | 用途 | 出现条件 |
| --- | --- | --- |
| 项目管理 | 打开子项目管理页（新建子项目、子项目任务与物料） | 本人是本项目或子项目的项目经理 |
| 计划管理 | 编辑项目计划（甘特），生成待下发任务 | 本人是本项目的项目经理 |
| 任务管理 | 打开子项目任务页，处理工单审核 | 本人是子项目经理或主项目经理 |
| 特性 | 打开特性处理页（分配、启动研发、分解、特性评审、作业评价、物料） | 本人是本项目或子项目的项目经理 |
| 数据 | 结构化查看项目全部执行数据与归档树 | 项目成员 |
| 归档 | 项目收口归档 | 项目已完成，且本人具备归档资格 |
| 发布产品版本 | 把已完成项目登记为产品发布版本 | 项目已完成 |
| 项目评审 | 发起主项目评审 | 全部子项目已完成 |
| 物料 / 费用 | 项目级物料与费用管理 | 本人是本项目的项目经理 |
| BOM | 结构化编辑项目 BOM | 项目经理 |

按钮不显示多数是身份不符或状态未到，而不是权限配置问题。

## 9.3 新建子项目

### 9.3.1 适用角色与目的

主项目经理。目的：按专业分工把主项目拆成可独立执行、独立评审的子项目。

### 9.3.2 入口

`项目管理 > 项目行【项目管理】 > 【新建子项目】`。

### 9.3.3 前置条件

- 主项目与根子项为 `SETUPED`（立项已批准）。
- 子项目经理、测试主管、系统工程人选已在对应资质名单中。
- 已确定本子项目的目标里程碑。

### 9.3.4 操作步骤

1. 打开项目行【项目管理】，进入子项目页签。
2. 点击【新建子项目】。
3. 填写子项目名称。
4. 选择子项目经理、测试主管、系统工程。
5. 选择目标里程碑（取自主项目里程碑）。
6. 设置评审时间，须早于目标里程碑日期。
7. 勾选纳入本子项目的特性。
8. 填写批准预算（按科目），不得小于所选特性开发预算合计。
9. 保存。

### 9.3.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 子项目名称 | 是 | 机构内可辨识 |
| 子项目经理 | 是 | `PJM` 成员 |
| 测试主管 | 是 | 本子项目测试工单的最终审核人 |
| 系统工程 | 是 | `SM` 成员 |
| 目标里程碑 | 是 | 取主项目里程碑；子项目评审须在其之前完成 |
| 评审时间 | 是 | 日期，早于目标里程碑 |
| 特性 | 是 | 至少一条；纳入后特性改挂本子项目 |
| 批准预算 | 是 | 各科目金额；不得小于所选特性开发预算合计 |

### 9.3.6 结果与留痕

子项目为 `SETUPED`；被选中的特性改挂该子项目，状态仍为 `SETUPED`（不因分解自动变成 `DEVELOPING`）；根子项预算按科目划出到子项目。

### 9.3.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提示批准预算不得小于所选特性开发预算合计 | 预算不足 | 增加预算或减少特性 |
| 评审时间保存被拒 | 不早于目标里程碑 | 改期或改目标里程碑 |
| 特性列表里没有想要的特性 | 已被其他子项目纳入 | 先在其他子项目中移出，或直接“分配”划转 |
| 保存后子项目经理看不到 | 未重新登录 | 退出重新登录；角色按任命即时计算 |

## 9.4 计划管理

### 9.4.1 适用角色与目的

主项目经理。目的：用甘特图编排项目计划，形成待下发任务，避免临时口头派工。

### 9.4.2 入口

`项目管理 > 项目行【计划管理】`。

### 9.4.3 操作步骤

1. 打开甘特视图，按特性或子项目展开行。
2. 新增计划行：填写任务名称、计划开始与完成时间、计划工时、责任人。
3. 拖动条形调整起止时间；依赖关系在同一特性内自动约束。
4. 保存计划。
5. 需要派工时，在计划行上生成任务并下发（生成后进入执行人的待办）。

### 9.4.4 结果与留痕

计划保存后写入项目计划表，甘特与“项目管理”列表的完工率、逾期数联动。计划只是排期，不改变特性状态；任务下发后才产生工单。

### 9.4.5 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 起止时间拖不动 | 被前置依赖约束 | 先调前置行 |
| 计划保存后逾期数增加 | 计划完成时间已过 | 调整计划或按实际完成时间收口 |
| 下发的任务执行人收不到 | 责任人不是在职成员 | 检查成员状态 |

## 9.5 特性分配（划转）

### 9.5.1 适用角色与目的

主项目经理。目的：把挂在根子项上的特性划转到合适的子项目，不改特性状态。

### 9.5.2 入口

`项目管理 > 项目行【特性】 > 特性处理 > 【分配】`。

### 9.5.3 前置条件

- 特性状态为 `SETUPED`。
- 目标子项目已创建且为 `SETUPED`。

### 9.5.4 操作步骤

1. 在特性处理列表勾选待划转特性。
2. 点击【分配】。
3. 选择目标子项目。
4. 确认。

### 9.5.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 特性 | 是 | 可多选，须同属当前项目 |
| 目标子项目 | 是 | 本项目的子项目 |

### 9.5.6 结果与留痕

特性的所属子项目变更，状态保持 `SETUPED`；子项目与根子项的预算按差额调整；特性过程记录一条“分配”动作。

分配**不会**让特性进入研发，启动研发需由目标子项目的项目经理单独操作。

### 9.5.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 分配按钮灰显 | 特性已启动研发 | 已启动的特性不再允许划转 |
| 目标子项目不在下拉 | 子项目未创建或已关闭 | 先创建子项目 |
| 分配后原项目经理仍能看到 | 仍是项目成员 | 查看权与操作权分离，不影响归属 |

## 9.6 启动研发

### 9.6.1 适用角色与目的

子项目经理（或主项目经理、机构管理员）。目的：把子项目内的特性从“已立项”推进到“研发中”，之后才允许下发研发工单。

### 9.6.2 入口

`项目管理 > 项目行【特性】 > 特性处理 > 勾选特性 > 【启动研发】`。

### 9.6.3 前置条件

- 特性为 `SETUPED`。
- 操作人必须是该特性所属子项目的项目经理。

### 9.6.4 操作步骤

1. 打开特性处理列表。
2. 勾选一条或多条特性。
3. 点击【启动研发】。
4. 确认。

### 9.6.5 结果与留痕

特性转 `DEVELOPING`；所属子项目转 `ONGOING`；主项目保持 `SETUPED`（主项目状态只随子项目评审与项目评审推进）。

### 9.6.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提示 `NO_PERMISSION` | 不是该特性所属子项目的项目经理 | 由该子项目经理操作 |
| 勾选后按钮灰显 | 特性已是 `DEVELOPING` 或更后状态 | 无需重复启动 |
| 启动后研发管理里还是空的 | 尚未下发研发工单 | 按 9.8 下发 |

## 9.7 特性分解与分解审批

### 9.7.1 适用角色与目的

子项目经理下发分解工单并审批子特性；系统工程师做整体复核（见 8.6）。目的：把大特性拆成可独立开发、可独立测试的子特性。

### 9.7.2 入口

- 下发分解：`项目管理 > 项目行【特性】 > 特性处理 > 特性行【分解】`。
- 分解审批：`项目管理 > 特性处理 > 分解审批`，或 `执行管理 > 分解审批工单`。

### 9.7.3 前置条件

- 主特性为 `SETUPED` 或 `DEVELOPING`。
- 分解执行人为本机构在职成员。

### 9.7.4 操作步骤（下发）

1. 在特性处理列表定位目标特性，点【分解】。
2. 选择分解执行人。
3. 填写计划提交时间与计划工时。
4. 填写任务说明，提交。

### 9.7.5 操作步骤（审批）

1. 执行人提交后，主特性转 `DECOMPOSED`，分解工单下一节点为本人。
2. 打开分解工单，逐条查看子特性：名称、描述、预算（按工时计算）、责任人。
3. 逐条核定预算后审批；不满意的子特性驳回给执行人修改。
4. 全部审批通过后，系统生成复核单给系统工程师。

### 9.7.6 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 分解执行人 | 是 | 在职成员，受负荷校验 |
| 计划提交时间 | 是 | 日期 |
| 计划工时 | 是 | 小时 |
| 子特性预算 | 审批时核定 | 由工时换算，合计不得超过主特性预算 |

### 9.7.7 结果与留痕

| 节点 | 状态 |
| --- | --- |
| 下发分解 | 主特性 `DECOMPOSED`；分解工单 `HANDLING` |
| 执行人提交 | 子特性 `SUBMIT`，下一节点本人 |
| 本人审批通过 | 子特性 `SETUP`；分解工单 `CHA_RECHECK`，生成复核单 |
| 复核通过 | 子特性 `SETUPED`；分解工单 `EVALUATE` |
| 复核不通过 | 子特性回 `SAVED`；分解工单回 `HANDLING` |
| 本人评价完成 | 分解工单 `COMPLETED` |

### 9.7.8 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 分解按钮不显示 | 特性状态不允许，或本人不是该子项目经理 | 核对状态与身份 |
| 子特性预算合计超主特性 | 工时填得过多 | 核定下调或让执行人重填 |
| 复核不通过后卡住 | 分解工单未回 `HANDLING` | 让执行人改后重提，会生成新复核单 |
| 主特性一直 `DECOMPOSED` | 子特性未全部归档 | 属正常，全部子特性归档后才收口 |

## 9.8 下发研发工单

### 9.8.1 适用角色与目的

子项目经理。目的：把特性的开发工作拆成工单派给执行人，明确工时、时间与任务说明。

### 9.8.2 入口

`研发管理 > 特性列表 > 特性行【研发管理】 > 下发任务`；也可从 `项目管理 > 任务管理` 进入。

### 9.8.3 前置条件

- 特性为 `DEVELOPING`。
- 执行人为本机构在职成员。

### 9.8.4 操作步骤

1. 打开研发管理页，定位目标特性。
2. 点击【下发任务】。
3. 选择工单类型：开发任务（默认）。
4. 选择执行人。
5. 填写计划工时、计划提交时间、任务说明。
6. 提交。

### 9.8.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 工单类型 | 是 | 开发任务／测试任务／复核任务，按用途选择 |
| 执行人 | 是 | 在职成员；系统按未来 5 个工作日日均负荷校验 |
| 计划工时 | 是 | 小时 |
| 计划提交时间 | 是 | 日期，受工作日历影响 |
| 任务说明 | 否 | 文本，建议写清交付物与验收点 |

### 9.8.6 结果与留痕

工单状态 `HANDLING`；执行人“执行管理”出现待办与角标；特性过程记一条“下发任务”；项目逾期数与健康度按计划时间联动。

### 9.8.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提示工作超负荷 | 执行人未来 5 个工作日日均负荷超上限 | 换人、延长计划时间或减少工时 |
| 下发任务按钮不显示 | 特性未启动研发，或本人不是该子项目经理 | 先启动研发 |
| 工单派错人 | 已进入执行人待办 | 由执行人在工单中退回，或由项目经理驳回后重派 |
| 评审期间下发主项目任务被拒 | 主项目正在评审 | 见 9.15，评审结束后再下发 |

## 9.9 任务审核与特性集成

### 9.9.1 适用角色与目的

子项目经理。目的：审核执行人提交的交付物，签发测试或复核工单，组织集成。

### 9.9.2 入口

`研发管理 > 特性列表 > 特性行【研发管理】 > 任务审核页签`。

### 9.9.3 页面内容

| 页签/区域 | 内容 |
| --- | --- |
| 任务审核 | 待审核的研发工单，含交付件与工时申报 |
| 测试/复核任务 | 对已审核工单签发测试工单或复核工单 |
| 特性集成 | 全部工单完成后出现，用于下发集成工单 |

### 9.9.4 操作步骤（审核）

1. 打开任务审核页签。
2. 打开目标工单，核对交付件、工作描述与工时申报。
3. 选择【通过】或【驳回】；驳回填写原因，工单回 `HANDLING`。
4. 工时异常时，在审核中调整核准工时。

### 9.9.5 操作步骤（签发测试）

1. 在“测试/复核任务”区点【下发】。
2. 选择测试执行人（通常为测试工程师）。
3. 填写任务说明（测试要点）与计划工时、时间。
4. 提交后测试工单为 `HANDLING`，被测研发工单保持 `SUBMIT`。

### 9.9.6 操作步骤（特性集成）

1. 确认该特性下全部工单已完成（未完成时“特性集成”按钮不出现）。
2. 点【特性集成】，选择集成执行人，填写说明。
3. 提交。特性转 `INTEGRATION`，集成工单为 `HANDLING`。

### 9.9.7 结果与留痕

| 动作 | 结果 |
| --- | --- |
| 审核通过 | 研发工单进入下一节点（评价人或测试人） |
| 审核驳回 | 工单回 `HANDLING`，执行人重做 |
| 签发测试 | 测试工单 `HANDLING`，特性仍 `DEVELOPING` |
| 下发集成 | 特性 `INTEGRATION`，集成工单 `HANDLING` |
| 集成工单评价完成 | 特性 `DEV_COMPLETE` |

### 9.9.8 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 审核页签为空 | 执行人未提交，或已审完 | 核对执行人待办 |
| 特性集成按钮不出现 | 仍有工单未完成 | 先推进测试与缺陷闭环 |
| 已提交工单想直接改状态 | 工单不允许越级处理 | 走驳回，不直接改 |
| 测试驳回后特性停住 | 测试工单回执行人 | 按测试意见修复后重提 |

## 9.10 作业评价

### 9.10.1 适用角色与目的

子项目经理（研发工单、分解工单、集成工单）或测试主管（测试工单）。目的：对完成的工单评分并给出评价意见，评价是工单收口与绩效计量的依据。

### 9.10.2 入口

`项目管理 > 项目行【特性】 > 特性处理 > 作业评价页签`；或 `执行管理 > 工单 > 评价`。

### 9.10.3 前置条件

- 工单状态为 `SUBMIT` 且下一节点为本人。
- 测试工单须先经测试主管审核完成。

### 9.10.4 操作步骤

1. 打开作业评价页签，定位待评价工单。
2. 查看交付件、工时申报与上游评分。
3. 填写评分（分制与阈值按机构绩效规则）。
4. 填写评价意见。
5. 提交。

### 9.10.5 结果与留痕

工单转 `COMPLETED`；评分记入绩效工时与绩效评分；**研发工单评价时填写评分会覆盖测试阶段给出的评分**，以项目经理评分为最终值。评价意见不可修改。

### 9.10.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 工单不在评价列表 | 测试未审核完成 | 先完成测试审核 |
| 评分想改 | 已收口 | 通过绩效调整流程处理，不改工单 |
| 评价后特性仍未 `DEV_COMPLETE` | 其他工单未完成 | 补齐其余工单与集成 |

## 9.11 物料管理（领料、退料、处置、BOM）

### 9.11.1 适用角色与目的

子项目经理为领料与退料的审批人、物料处置的复核人；集成阶段执行人编辑 BOM。目的：控制研发领料的合理性，并形成可归档的物料清单。

### 9.11.2 入口

| 动作 | 入口 |
| --- | --- |
| 领料审批、退料审批 | `执行管理 > 待办 > 领料单／退料单`；或 `物料管理` |
| 物料处置复核 | `研发管理 > 特性行【物料管理】`；或 `物料管理` |
| BOM 编辑 | `执行管理 > 集成工单 > 任务处理 > 特性物料清单 BOM 编辑` |

### 9.11.3 领料审批

1. 执行人在研发工单或集成工单中提交物料申请，单价自动取当前库存单价。
2. 项目经理打开领料单，核对物料、数量、用途。
3. 批准后单据进入“待发料”，库存不变。
4. 由物料管理员发料确认后库存才扣减。

审批弹窗中单价为只读，任何人不能改；改价只能通过重新入库影响加权平均单价。

### 9.11.4 退料审批

1. 执行人对已发料的领料单发起退料，选择退回仓库与数量。
2. 项目经理审批，批准后为“待收料”，库存不变。
3. 物料管理员收料确认后库存回增，原领料单数量相应扣减。

只有“已发料”状态的领料单可以退料；待发料状态下发起退料会被拒。

### 9.11.5 物料处置复核

1. 执行人对费用化（非资产化）的领料物料提交处置记录。
2. 项目经理在特性物料页复核批准。
3. 特性评审发起的前提条件要求本特性的费用化物料处置全部完成，未复核时无法发起评审。

### 9.11.6 BOM 编辑（集成阶段）

1. 执行人在集成工单的“任务处理”中打开“特性物料清单 BOM 编辑”。
2. 点【物料拣选】带入本项目领用过的物料，再按实际装配调整行。
3. 每一编辑行必须填写供应商与供货税率。
4. 提交后生成提交快照，清单 `SUBMIT`；项目经理在特性物料页复核。

物料拣选只列未被取消、未被驳回的领料单中的物料；已取消的领料单不会带入。

### 9.11.7 结果与留痕

领料与退料形成库存流水；预算的物料执行额按“领料金额减退料金额”计入；BOM 提交生成快照，特性评审时锁定为 `LOCKED`。

### 9.11.8 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提示 `MATERIAL_STOCK_SHORT` | 申请数量超库存 | 减少数量或补入库 |
| 想改单价 | 单价只读 | 不接受手工改价 |
| 待发料状态下不能退料 | 尚未出货 | 等发料完成后再退 |
| BOM 编辑不能提交 | 行内缺供应商或供货税率 | 补全再提交 |
| 评审发起被拒，提示处置未完成 | 有费用化物料未处置 | 由执行人提交处置，项目经理复核 |

## 9.12 费用管理

### 9.12.1 适用角色与目的

子项目经理、主项目经理。目的：审批研发过程中非物料的费用申请（差旅、外协、检测等），控制在项目预算内。

### 9.12.2 入口

`项目管理 > 项目行【费用】`；或 `执行管理 > 费用申请单`。

### 9.12.3 操作步骤

1. 打开费用申请单，核对费用科目、金额、事由与附件。
2. 核对所属预算科目余额是否足够。
3. 批准或驳回；驳回填写原因。
4. 批准后进入下一节点（如最终管理人终审或财务办理）。

### 9.12.4 结果与留痕

批准后费用占用相应预算科目；费用执行额进入预算执行率与绩效统计。

### 9.12.5 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提交被拒，提示预算不足 | 科目余额不足 | 减少金额或由产品经理申请预算调整 |
| 费用单看不到 | 不在本人审批范围 | 核对费用归属项目 |
| 已批准想撤回 | 已进入下一节点 | 由下一节点驳回或走预算调整 |

## 9.13 发起特性评审

### 9.13.1 适用角色与目的

子项目经理。目的：特性开发与集成完成后组织评审，决定归档、是否发布为 CBB、是否需要增补或驳回。

### 9.13.2 入口

`研发管理 > 特性列表 > 特性行【研发管理】 > 特性评审页签`；或 `项目管理 > 特性处理 > 特性评审`。

### 9.13.3 前置条件

四项必须同时满足：

1. 特性为 `DEV_COMPLETE`。
2. 特性物料清单已提交（`SUBMIT` 或已锁定）。
3. 本特性的费用化物料处置全部完成并经项目经理复核。
4. 评分、工时等作业评价已收口。

### 9.13.4 操作步骤

1. 打开特性评审页签。
2. 核对评审对象信息与物料清单。
3. 选择三名评审委员（通常为监管委员与系统工程师）。
4. 填写评审说明（评审要点、关注风险）。
5. 提交。

### 9.13.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 评审委员 | 是 | 一般为 3 人；同一人不得重复 |
| 评审说明 | 否 | 文本 |
| 评审组长 | 否 | 系统缺省取本预立项产品经理，不可在发起时改选 |

### 9.13.6 结果与留痕

评审主单 `HANDLING`，特性转 `REVIEW`；三名委员各收到委员单；组长在“执行管理”收到审结任务与角标。组长审结后按四种结论分别处理（见 7.6.5），项目经理需在“评审通知”中确认结果，主单才转 `COMPLETED`。

### 9.13.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提示 `REVIEW_ALREADY_IN_PROGRESS` | 同一特性已有进行中的评审 | 等当前评审结束 |
| 发起页缺物料清单 | 未提交 BOM | 由执行人先提交清单 |
| 前置条件提示处置未完成 | 费用化物料未处置或未复核 | 按 9.11.5 补做 |
| 评审结论不是想要的 | 审结权在组长 | 在委员意见与评审说明中提前对齐，不改审结结果 |
| 评审驳回后停住 | 特性回 `INTEGRATION` | 修复后重新提交集成工单并评价，再次发起评审 |

## 9.14 发起子项目评审

### 9.14.1 适用角色与目的

子项目经理。目的：本子项目全部特性归档后做子项目级评审，形成子项目基线与（可选的）集成级 CBB。

### 9.14.2 入口

`项目管理 > 项目行【项目管理】 > 任务管理 > 子项目评审页签`。

### 9.14.3 前置条件

- 本子项目全部特性已 `ARCHIVED`。
- 子项目物料清单已汇总并提交（`SUBMIT`）。

### 9.14.4 操作步骤

1. 进入子项目评审页签。
2. 在 BOM 编辑区汇总并提交子项目物料清单。
3. 填写评审标题与描述。
4. 选择评审委员（通常与特性评审同一批人）。
5. 提交。

### 9.14.5 结果与留痕

主单 `HANDLING`，执行人为评审组长（缺省产品经理），子项目转 `REVIEW_SUBP`；子项目详情显示测试主管与系统工程姓名。组长审结“通过”后：子项目转 `COMPLETE`，子项目物料清单 `LOCKED`，生成子项目基线，派发 CBB 定义工单给组长，评审通知派给项目经理。

### 9.14.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 发起按钮不显示 | 仍有特性未归档 | 先完成剩余特性的评审与通知确认 |
| 物料清单提交失败 | 明细为空或缺供应商 | 补全明细 |
| 审结后没生成 CBB | 组长选“不发布” | 属正常，集成级 CBB 非必选 |
| 子项目评审后子项目仍未完成 | 组长未审结或通知未确认 | 核对主单状态 |

## 9.15 发起主项目评审

### 9.15.1 适用角色与目的

主项目经理。目的：全部子项目完成后对主项目做整体评审，评审通过后项目才能发布与归档。

### 9.15.2 入口

`项目管理 > 项目行【项目评审】`。评审管理页面只有列表，不提供发起入口。

### 9.15.3 前置条件

- 全部子项目为 `COMPLETE`。
- 项目预算已核对（评审通过后预算转 `COMPLETE`）。

### 9.15.4 操作步骤

1. 在项目管理列表点击项目行【项目评审】。
2. 填写评审标题、描述与截止时间。
3. 选择三名评审委员。
4. 提交。

### 9.15.5 结果与留痕

主单 `HANDLING`，子项目标识等于项目标识，执行人为监管委员，项目转 `REVIEW_PRO`。评审期间对主项目下发主项目任务会被拒（`PROJECT_JOB_FORBIDDEN_WHEN_REVIEWING`）。组长审结“通过”后项目与根子项转 `COMPLETE`，项目预算转 `COMPLETE`，评审通知派给项目经理；项目经理确认后主单 `COMPLETED`。

### 9.15.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 项目评审按钮不显示 | 仍有子项目未完成 | 收口子项目评审 |
| 评审期间下发任务被拒 | 评审锁定 | 评审结束或等审结后下发 |
| 评审结论驳回 | 评审不通过 | 按意见整改后重新发起 |
| 项目完成后仍不能归档 | 归档人资格不符 | 归档人限产品经理与监管委员 |

## 9.16 里程碑评审

### 9.16.1 适用角色与目的

主项目经理（兼任组长）与评审委员。目的：在里程碑节点对阶段完成情况做过程性评审，结论以文字形式留档，不改变特性与项目状态。

### 9.16.2 入口与触发

里程碑评审不由人工发起：系统每天扫描本机构项目，对“里程碑时间在 1 天内、`isReviewed` 为 1”的里程碑，自动给主项目经理派一张工单，任务名为“发起评审:{里程碑名称}-里程碑评审”，类型 `REVIEW_MILESTONE_PRE`。入口：`执行管理 > 任务列表 > 该工单`。

`isReviewed`：0 新建、1 已派里程碑任务、2 已派评审发起单。派单后置 2，同一里程碑不会再派第二次。

### 9.16.3 前置条件

- 本人是该主项目的项目经理。
- 里程碑任务（`TASK_MILESTONE`）已下发，`isReviewed` 已到 1。
- 该里程碑尚未发起过评审（无 `HANDLING` 状态的发起单）。

### 9.16.4 操作步骤

1. 打开工单。上半部为任务信息（项目、子项目、执行人、任务工时、计划提交时间、提交倒计时、任务描述、附件），只读。
2. 在下半部“里程碑阶段评审申请表”填写：评审标题、任务描述、评审委员、提交时间、附件。
3. 点击【提交评审申请表】。

### 9.16.5 字段说明

| 字段 | 规则 |
| --- | --- |
| 评审标题 | 必填；建议“{里程碑名称}-里程碑评审” |
| 任务描述 | 必填；写清评审范围与需委员确认的事项 |
| 评审委员 | 必填；穿梭框从本机构成员中选，至少 1 人 |
| 提交时间 | 必填；委员提交意见的截止日期，缺省取里程碑评审时间 |
| 附件 | 可选；阶段交付件、测试记录、成本数据 |

### 9.16.6 结果与留痕

- 系统生成里程碑评审主单（`REVIEW_MILESTONE`），组长为主项目经理，每位评审委员各得一张委员单（`REVIEW_COO`）。
- 发起单自动转 `COMPLETED`，过程记录“已发起里程碑评审”；同一发起单不能重复提交，非 `HANDLING` 时返回 `JOB_ITEM_STATUS_INVALID`。
- 评审管理列表新增一行，类型为“里程碑评审”；里程碑 `isReviewed` 保持 2，系统不再重复派单。

### 9.16.7 审结与归档

1. 委员在 `执行管理 > 委员单` 提交意见后，组长在 `评审管理 > 评审行【评审管理】` 审结。
2. 里程碑评审**没有结论选择项**，系统固定按“通过”处理；结论必须写在“工作描述”正文（10 至 5000 字），页面提示“里程碑评审结论请在评审结论中详细说明”。
3. 需后续动作时，评审后另发任务工单给相关人员，不由评审单派生增补任务。
4. 审结后主单 `COMPLETED`，评审行出现【归档】；里程碑评审不受“子工单全部完成”限制，审结即可归档。

### 9.16.8 与其他评审的差异

| 维度 | 特性评审（9.13） | 子项目评审（9.14） | 主项目评审（9.15） | 里程碑评审 |
| --- | --- | --- | --- | --- |
| 发起人 | 子项目经理 | 子项目经理 | 主项目经理 | 系统定时派单给主项目经理 |
| 组长 | 产品经理 | 产品经理 | 监管委员 | 主项目经理 |
| 结论选项 | 四种 | 四种 | 四种 | 无，固定通过 |
| 是否发布 CBB | 可选特性 CBB | 可选集成级 CBB | 无此项 | 无此项 |
| 归档条件 | 子工单全部完成 | 子工单全部完成 | 子工单全部完成 | 审结即可归档 |
| 对对象状态的影响 | 特性 `ARCHIVED` | 子项目 `COMPLETE` | 项目 `COMPLETE` | 不改特性与项目状态 |

### 9.16.9 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 收不到发起单 | 里程碑任务未下发，或已发起过 | 先下发里程碑任务；已发起的在评审管理中继续 |
| 提交被拒“工单状态无效” | 发起单已 `COMPLETED` 或已被处理 | 在评审管理查看该里程碑是否已有评审行 |
| 委员未收到委员单 | 未选委员，或选到本机构以外成员 | 重新发起时核对委员名单 |
| 审结页没有结论可选 | 里程碑评审设计如此 | 结论写入工作描述 |
| 评审行没有归档按钮 | 主单未 `COMPLETED` | 先审结 |

## 9.17 归档

### 9.17.1 适用角色与目的

项目完成后的收口动作。目的：把项目及其全部过程资料固化为归档数据并锁定。

### 9.17.2 入口

`项目管理 > 项目行【归档】`。

### 9.17.3 前置条件

- 项目为 `COMPLETE`。
- 操作人具备归档资格：产品经理或监管委员；其他人操作会返回 `PROJECT_ARCHIVE_ACTOR_INVALID`。

### 9.17.4 操作步骤

1. 确认项目状态为已完成。
2. 点击项目行【归档】。
3. 核对归档范围（特性、物料清单、测试与缺陷、评审记录、交付件）。
4. 确认归档。

### 9.17.5 结果与留痕

项目转 `ARCHIVED`；全部关联数据只读；产品管理中的已发布产品仍可继续发布版本与修订。

### 9.17.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 提示归档人无效 | 操作人不是产品经理或监管委员 | 由产品经理或监管委员归档 |
| 归档按钮不显示 | 项目未完成 | 先完成项目评审 |
| 归档后想改数据 | 归档已锁定 | 通过迭代或质量流程处理，不解除归档 |

## 9.18 发布产品版本

### 9.18.1 适用角色与目的

项目经理在项目管理列表也可发起产品发布，与产品经理在产品管理中的发布等价。

### 9.18.2 入口

`项目管理 > 项目行【发布产品版本】`；或 `产品管理 > 已发布产品 > 【发布产品版本】`（产品经理侧）。

### 9.18.3 前置条件

- 主项目为 `COMPLETE`。
- 项目已有全部特性归档与项目基线。

### 9.18.4 操作步骤

1. 点击【发布产品版本】。
2. 选择产品配置（缺省为现行配置）。
3. 填写发布说明。
4. 上传交付文件。
5. 提交。

### 9.18.5 结果与留痕

产品由 `DRAFT` 转 `ACTIVE`；产品版本列表新增一个发布版本（版本号取项目主开发版本）；同时生成发布基线，含各特性锁定版本、CBB、物料清单快照与交付文件。重复点击不会新增重复发布版本。

### 9.18.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 按钮不显示 | 项目未完成 | 先完成项目评审 |
| 再次点击无新增 | 已存在同版本发布 | 属正常，一个主开发版本只发布一次 |
| 发布基线缺 CBB | 特性未发布为 CBB | 属正常，CBB 非必选 |

## 9.19 数据视图与 BOM

| 入口 | 用途 |

| 项目行【数据】 | 结构化查看项目全部执行数据与归档树，按特性—子特性—工单—交付件展开，只读 |

## 9.20 边界与交接

| 不做的事 | 由谁做 |
| --- | --- |
| 预立项的新建、修订、关闭 | 产品经理（7.2） |
| 发起立项、填写立项预算 | 产品经理（7.5） |
| 审批立项 | 监管委员（14.3） |
| 给出特性审核意见、分解复核 | 系统工程师（8.5、8.6） |
| 审结评审、决定是否发布 CBB | 评审组长，缺省产品经理（7.6） |
| 里程碑评审的发起与审结 | 主项目经理（9.16） |
| 组件级测试下发、测试工单最终审核 | 测试主管（10.4） |
| 质量单的处理与结案 | 产品经理（7.8） |
| 发料确认、收料确认、入库 | 物料管理员（13.4、13.6） |
| 团队与任命、职级与费率 | 机构管理员（5.4、5.6） |

交接清单：

1. 子项目建好后，通知子项目经理重新登录以获取操作权。
2. 分解工单下发后，待系统工程师复核通过再评价，避免流程倒挂。
3. 集成完成后先提交特性物料清单，再发起评审，否则前置条件不满足。
4. 评审结论为“增补”时，增补任务由本项目经理承接，完成后再由组长复审。
5. 主项目评审通过后，把发布与归档交给产品经理或监管委员。

## 9.21 常见问题

| 问题 | 答复 |
| --- | --- |
| 为什么我看不到某个项目 | 不是该项目或其子项目的成员，或项目不在本人所属机构 |
| 主项目经理能否直接操作子项目内的工单 | 只能查看；工单下发与评价归子项目经理 |
| 特性能不能终止 | 立项后一律不允许终止，终止按钮不显示 |
| 为什么子项目建了特性还是 `SETUPED` | 子项目创建不改变特性状态，需单独“启动研发” |
| 领料单价能不能改 | 不能，只读，取库存移动加权平均价 |
| 评审组长能不能改选 | 特性与子项目评审缺省为产品经理，发起时不可改；项目评审缺省为监管委员 |
| 分解后主特性为什么一直 `DECOMPOSED` | 子特性未全部归档，属正常 |
| 逾期数怎么清零 | 按实际完成时间收口工单或调整计划时间 |
| 能否给自己下发任务 | 可以，但不建议，评分会覆盖自评，绩效口径按机构规则 |
| 项目废弃由谁做 | 最终管理人（6.6），项目经理无此按钮 |
