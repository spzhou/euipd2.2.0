# 第 6 章 最终管理人（`UltiMng`）

## 6.1 角色定位与全权范围

最终管理人是机构内唯一的“身份全权”角色：本机构 25 项菜单与全部页签、按钮均对其开放。它既承担治理职责（权限覆盖、流程定义），也能在缺位时代办关键动作。

| 项 | 说明 |
| --- | --- |
| 角色码 | `UltiMng`，旧称“老板/BOSS”，历史数据中的旧值由系统兼容 |
| 菜单 | 25 项，含团队管理、假日设置、仓库管理、库存管理、全部页签 |
| 独占按钮 | 编辑分类 `520101`、废弃 `520102`、创建直接立项 `520103`、档案操作 `520301` |
| 独占菜单 | 权限配置 `5226`、流程配置 `5227`（侧栏入口已隐藏） |
| 机构覆盖 | 可为本机构其他角色调整菜单，覆盖对其本人与管理员无效 |
| 资质名单 | 读取时自动计入委员会、产品经理、项目经理、系统工程师四份名单 |
| 任命 | 由平台超管在“机构/团队 > 设置最终管理人”指定，每机构一人 |

注意两点：一是最终管理人不必是机构管理员，两者分离；二是最终管理人改设后，原最终管理人自动移出四份资质名单，新最终管理人自动进入。

## 6.2 与机构管理员的差异

| 能力 | `ADMIN` | `UltiMng` |
| --- | --- | --- |
| 团队管理、假日设置 | 有 | 有 |
| 绩效/盘点、绩效管理 | 有 | 有 |
| 物料盘点页签 | 有 | 有 |
| 预立项、立项、评审、产品、质量 | 无 | 有 |
| 项目管理、研发管理、测试管理 | 无 | 有 |
| 物料、仓库、库存 | 无 | 有 |
| 预算管理、系统工程、特性仓库 | 无 | 有 |
| 直接立项、编辑分类、废弃 | 无 | 有 |
| 档案操作 | 无 | 有 |
| 权限配置、流程配置 | 无 | 有 |
| 菜单数 | 12 | 25 |

同一人同时是管理员与最终管理人时按 25 项计；改设最终管理人后，原管理员回落到 12 项。

## 6.3 直接立项

### 6.3.1 适用角色与目的

仅最终管理人（按钮 `520103`）。目的：在没有预立项的情况下直接建立项目，用于紧急立项、内部预研、客户插单等场景。

### 6.3.2 入口

`研发管理 > 立项管理 > 【创建直接立项项目】`。

### 6.3.3 前置条件

- 已明确项目名称与唯一项目代码。
- 已确定监管委员、产品经理、项目经理、系统工程、测试主管人选（须已在资质名单或成员中存在）。
- 已准备预算与里程碑。

### 6.3.4 操作步骤

1. 进入立项管理，点击【创建直接立项项目】。
2. 填写项目基本信息：名称、代码、分类、所属产品与版本（如适用）。
3. 指定监管委员、产品经理、项目经理、系统工程、测试主管与核心成员。
4. 设置激励政策、计划发布时间。
5. 建立里程碑，并为每项特性指定本项目里程碑。
6. 填写预算表（材料费、工时费、其他费用）。
7. 选择特性并纳入本项目。
8. 保存为草稿，核对后提交。

### 6.3.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 项目名称 | 是 | 机构内可辨识 |
| 项目代码 | 是 | 机构内唯一；重复时不保存 |
| 项目分类 | 否 | 取自立项分类，可由最终管理人维护 |
| 监管委员 | 是 | 一般为 `IPMT` 成员 |
| 产品经理 | 是 | `PDM` 成员 |
| 项目经理 | 是 | `PJM` 成员 |
| 系统工程 | 是 | `SM` 成员 |
| 测试主管 | 是 | 立项后据此产生 `TM` |
| 核心成员 | 否 | 参与执行的成员 |
| 激励政策 | 否 | 文本 |
| 计划发布时间 | 否 | 日期 |
| 里程碑 | 是 | 至少一个，供特性指定 |
| 特性清单 | 是 | 直接立项可纳入已批准特性；不纳入时为空项目 |
| 预算表 | 是 | 各科目金额；特性预算之和不得超过项目预算合计 |

### 6.3.6 结果与留痕

提交后项目进入待审批，由监管委员在“立项管理”审批。批准后项目与根子项同时为 `SETUPED`，特性随项目进入已立项状态，并生成项目基线。未批准前可撤回，撤回只允许在编辑中状态。

### 6.3.7 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 按钮不显示 | 不是最终管理人 | 由平台超管设置最终管理人 |
| 项目代码重复 | 与既有项目冲突 | 换代码 |
| 特性预算超项目预算 | 预算之和不平 | 调整预算或减少特性 |
| 提交后无人可审 | 未指定监管委员 | 补指定后重新提交 |
| 想改已提交的项目 | 已进入待审批 | 撤回后再改 |

## 6.4 立项管理的其他入口

立项管理页面上还有两个与最终管理人相关但不独占的能力：

| 入口 | 说明 | 谁可操作 |
| --- | --- | --- |
| 创建特性开发项目 | 由预立项发起，同一机构只能有一个特性开发项目；已存在时按钮不再出现 | 产品经理、产品总监；最终管理人可代办 |
| 追加 | 把本项目相关特性追加到已立项项目，不新建立项 | 产品经理；最终管理人可代办 |
| 立项（审批） | 对提交的立项申请批准 | 监管委员；最终管理人可代办 |

“追加”不产生新项目，只把特性纳入既有项目的范围，因此不改变既有项目的代码与里程碑结构。直接立项项目不显示“追加”。

## 6.5 立项分类

### 6.5.1 适用角色与目的

仅最终管理人（按钮 `520101`）。目的：维护立项分类，供项目归类和列表筛选使用。

### 6.5.2 入口

`研发管理 > 立项管理 > 分类区【添加分类】/【管理分类】`。

### 6.5.3 操作步骤

1. 点【添加分类】，填写分类名称后保存，分类出现在分类页签中。
2. 点【管理分类】对既有分类改名或调整结构。
3. 删除分类前确认该分类下无项目，否则先转移项目。

### 6.5.4 结果与留痕

分类立即生效，项目列表按分类页签组织。分类只是归类，不影响流程与权限。

### 6.5.5 异常与处置

分类重名不保存；分类下有项目时不允许删除，需先把项目改到其他分类。

## 6.6 项目废弃

### 6.6.1 适用角色与目的

仅最终管理人（按钮 `520102`）。目的：终止不再推进的项目，同时收口未完成的特性与工单。

### 6.6.2 入口

`研发管理 > 立项管理 > 项目行【废弃】`。

### 6.6.3 前置条件

- 项目已立项或执行中。
- 确认项目不再继续，且已通知相关产品经理与项目经理。

### 6.6.4 操作步骤

1. 在项目行点击【废弃】。
2. 填写废弃原因（必填）。
3. 确认。

### 6.6.5 字段说明

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 废弃原因 | 是 | 文本，用于留痕 |

### 6.6.6 结果与留痕

1. 项目转关闭，未结束特性写为已废弃，未结束工单写为已取消。
2. 已归档特性、已完成的评审不受影响。
3. 与项目关联的预算停止执行，未使用额度不再释放为新预算。
4. 办理记录保留废弃人与原因，便于追溯。

### 6.6.7 异常与处置

废弃不可逆，误操作只能重建项目。项目已归档时不需要废弃；只是想暂停时建议保留项目并调整计划，不要废弃。

## 6.7 权限配置（机构菜单覆盖）

### 6.7.1 适用角色与目的

仅最终管理人（资源号 `5226`）。目的：在平台模板基础上，为本机构其他角色增减菜单与按钮。

### 6.7.2 入口

`研发管理 > 权限配置`。**该菜单已从侧栏注释下线**，常规操作须由实施人员直接访问 `/system/tenant-ui-policy` 或经接口维护；本节描述页面规则，供授权维护时使用。

### 6.7.3 页面规则

| 规则 | 说明 |
| --- | --- |
| 可调整对象 | 本机构其他角色；管理员列与最终管理人列为锁定列，不可改动 |
| 固定授予 | 团队管理、假日设置只属管理员与最终管理人；仓库、库存只属最终管理人与物料管理员 |
| 不可取消 | 物料管理员的物料管理、全员的我的邮件 |
| 联动 | 勾选模板以外的菜单时，同时授予该菜单所属模块的操作；取消模板内的菜单时，撤回该模块 |
| 生效 | 保存后对应用户重新登录生效 |
| 恢复 | 【全部恢复默认】清空本机构全部调整；每列可【恢复本列默认】 |

### 6.7.4 平台模板升级后的处理

页面顶部显示“平台模板差异”：本机构保存时基于的模板版本与当前版本。平台新增的资源不会自动加入已调整过的角色，需要：

1. 点【并入新增资源】把平台新增项并入本机构调整。
2. 核对新增项是否应授予该角色。
3. 点【保存】。保存后以当前模板为新基准，未并入的新增项不再列出。

### 6.7.5 结果与留痕

保存后本机构覆盖记录更新，页面提示已保存；被调整角色的成员重登后菜单变化。若有未保存修改，离开页面会提示将丢失。

### 6.7.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 本机构调整显示不出来 | 保存的记录无法解析 | 页面按平台默认显示，重新保存或恢复默认修正 |
| 平台加了新菜单，本机构某角色没有 | 覆盖基于旧模板 | 按 6.7.4 并入后保存 |
| 改了管理员列 | 锁定列不可改 | 管理员与最终管理人按身份固定 |
| 想给某角色开仓库 | 仓库只属最终管理人与物料管理员 | 改由物料部负责人取得 `MATM` |

## 6.8 流程配置

### 6.8.1 适用角色与目的

仅最终管理人（资源号 `5227`）。目的：查看全部流程的流程图，绘制并发布本机构流程定义，按业务主键查看已启动实例的进度。

### 6.8.2 入口

`研发管理 > 流程配置`。**侧栏已注释下线**，需要时直接访问 `/customer/flow`。

### 6.8.3 页面构成

| 页签 | 用途 |
| --- | --- |
| 流程图 | 查看全部既有流程的图形与节点说明 |
| 设计 | 绘制本机构流程定义，保存草稿与发布版本 |
| 进度 | 按业务主键查看某张单据当前实例走到哪个节点 |

### 6.8.4 操作步骤（设计）

1. 进入“设计”页签。
2. 选择业务类型，新建草稿或按历史版本建草稿。
3. 调整节点、审批人与分支条件。
4. 保存草稿，核对后发布。
5. 在“进度”页签以业务主键验证新实例是否按新定义流转。

### 6.8.5 结果与留痕

发布后新启动的实例按新版本流转，已启动实例保持原路径。流程定义有版本，可按历史版本重新建草稿，便于回退。

### 6.8.6 异常与处置

| 现象 | 原因 | 处置 |
| --- | --- | --- |
| 改了流程但单据没变 | 已启动实例走原版本 | 新建实例验证；不要改在办单据 |
| 发布后卡在某节点 | 节点审批人未配置或为空 | 补齐审批人后重新发布 |
| 找不到入口 | 侧栏已下线 | 直接访问 `/customer/flow` |

费用、档案、质量、物料等业务页面仍走原办理入口，流程配置只改变流转路径，不替代页面操作。

## 6.9 档案操作

### 6.9.1 适用角色与目的

仅最终管理人（按钮 `520301`）。目的：对档案做归档、移动等管理动作，普通成员只能上传与申请。

### 6.9.2 入口

`研发管理 > 档案管理 > 文件行操作`。

### 6.9.3 操作步骤

1. 进入档案管理，定位文件。
2. 使用行内档案操作按钮（归档、移动等）执行管理动作。
3. 按提示确认。

### 6.9.4 结果与留痕

档案的目录归属与状态变化，操作人与时间记入文件记录。普通成员的下载与申请不受影响。

### 6.9.5 异常与处置

看不到档案操作按钮：该按钮只授最终管理人。归档后成员仍可按目录检索与申请下载。

## 6.10 仓库管理与库存管理

最终管理人是除物料管理员之外唯一能看到这两个菜单的角色。

| 菜单 | 资源号 | 主要用途 | 详细操作 |
| --- | --- | --- | --- |
| 仓库管理 | `5223` | 仓库清单、启用停用 | 13.2 |
| 库存管理 | `5225` | 入库录入与导入、库存查询、盘点调整、流水 | 13.3 至 13.5 |

两者与物料管理员看到的界面一致，区别在职责分工：日常维护建议由物料管理员执行，最终管理人在物料管理员缺位时代办。物料申请与发料确认在“物料管理”（`5210`），见 13.7。

## 6.11 代批与越权红线

最终管理人“身份全权”指菜单与操作权限，不等于可以替任何人做任何事。以下边界必须遵守：

| 场景 | 是否可代办 | 说明 |
| --- | --- | --- |
| 立项审批 | 可以 | 以监管委员身份审批，留痕为本人 |
| 评审审结 | 可以 | 需为评审委员或被指派 |
| 成员任命 | 可以 | 团队管理资质设置 |
| 直接立项 | 可以 | 独占按钮 |
| 他人名下工单提交 | 不可以 | 工单只能由执行人处理 |
| 改他人已提交单据内容 | 不可以 | 只能驳回或要求撤回 |
| 代替他人做绩效申报 | 不可以 | 工时申报须本人 |
| 变更机构管理员 | 不可以 | 归平台超管 |

代办会产生办理记录，评审与审计时以记录为准。能用流程解决的事项不要用代办绕过。

## 6.12 常见问题

| 问题 | 处置 |
| --- | --- |
| 侧栏没有权限配置、流程配置 | 两菜单已下线；直接访问地址或经接口维护 |
| 改了权限配置没生效 | 被调整角色需重新登录 |
| 想取消物料管理员的物料管理 | 不可取消，属固定授予 |
| 想给管理员加立项菜单 | 管理员列锁定，无法调整；需要时改设最终管理人 |
| 直接立项后没有特性可选 | 直接立项可建空项目，或在特性仓库先建立特性 |
| 废弃项目后预算还能用吗 | 不能，未使用额度不再释放 |
| 流程发布后旧单据怎么办 | 旧实例按原版本走完，不追溯 |
| 能否有两个最终管理人 | 不能，每机构一人 |
