# 第 1 章 文档说明

## 1.1 编写目的与读者对象

本书记录 EUIPD 研发管理系统投入运行后，各角色在浏览器上完成本职工作的操作方法与判定依据。写作口径统一为“谁、在哪个页面、按什么顺序、填什么、得到什么结果、做不到时是什么原因”。

| 读者 | 关注章节 | 使用方式 |
| --- | --- | --- |
| 平台超级管理员 | 第 3、4 章 | 开户与设最终管理人，一次读完后按第 4.9 节交接 |
| 机构管理员 | 第 3、5 章 | 首日建团队与任命，之后按增减人员维护 |
| 最终管理人 | 第 3、6、16 章 | 全权操作与代批边界 |
| 产品经理、项目经理、系统工程师 | 第 3 章 + 本角色章 + 第 16 章 | 日常主用；遇到驳回、评审结论查第 17 章 |
| 测试、质量、法规、总监、物料、监管委员 | 第 3 章 + 本角色章 | 按本角色的菜单清单照做 |
| 普通成员 | 第 3、15 章 | 需求、工单、档案、邮件四件事 |
| 实施、培训、支持 | 第 2、16、18 章与附录 | 培训按主线讲，支持按速查表查 |

## 1.3 阅读路径

三条路径对应三种使用场景，可按需切换：

1. **按角色读**：第 3 章打底，再读本角色章。适合新成员入职与岗位轮换。
2. **按流程读**：直接读第 16 章，按阶段顺序走一遍。适合培训与演示，也适合排查“单子卡在谁那里”。
3. **按菜单查**：从附录 A 找到菜单资源号，再跳转到对应章节的具体条目。适合日常支持。

角色分册与主线的关系：分册回答“怎么做”，主线回答“什么时候做、做完交给谁”。同一操作不在两处重复描述字段与校验。

## 1.4 体例约定

### 1.4.1 路径与按钮

- 菜单路径写作 `菜单 > 页签 > 【按钮】`，例如 `项目管理 > 子项 > 【新建子项目】`。
- 页面按钮统一加【】，页签、列名、字段名不加。
- 路由与接口仅在附录 B 出现，正文不写接口路径；需要排查时按附录 B 反查。

### 1.4.2 状态与角色

- 业务状态码大写等宽，如 `SETUPED`、`DEV_COMPLETE`；中文对照见第 18.4 节。
- 角色码大写等宽，如 `PDM`；中文名与菜单数见第 2.3 节。
- 拒绝码与错误码等宽，如 `NO_PERMISSION`；全表见第 18.5 节。

### 1.4.3 操作条目七段式

每个操作条目固定七段，缺项时写“无”：

| 段 | 写作要求 |
| --- | --- |
| 适用角色与目的 | 一行说明谁能做、做完得到什么 |
| 入口 | 三级路径，含页签与按钮 |
| 前置条件 | 单据状态、前置单据、必要任命 |
| 操作步骤 | 编号步骤，逐步到按钮与弹窗；分步提交的写明每步状态 |
| 字段说明 | 表格：字段 / 必填 / 规则 / 示例 |
| 结果与留痕 | 状态前后、下一节点责任人、角标、办理记录 |
| 异常与处置 | 常见不成立的原因与处理办法（不逐字引用页面提示） |

### 1.4.4 其他约定

- 本书不写口令明文，演示账号见附录 C，口令以《测试账号》为准。
- 截图仅作示意，界面文案随版本微调；以页面实际显示与本书状态码为准。
- 涉及“仅最终管理人”“仅机构管理员”等限定，均以平台模板为准，机构覆盖不改变这两类身份的菜单。

## 1.5 名词表

| 名词 | 含义 |
| --- | --- |
| IPD | 集成产品开发。本书指系统承载的研发管理流程体系 |
| 机构 / 团队 | 多租户下的一家组织。机构标识即租户标识，业务数据按机构隔离 |
| 平台超级用户 | 机构标识为 `fm4ek0Zy` 的特殊机构，其管理员即平台超级管理员 |
| 最终管理人 | 每机构一人的身份全权角色 `UltiMng`，旧称“老板/BOSS” |
| 机构管理员 | 机构联系电话对应的账号，角色 `ADMIN`，只做人与日历 |
| 任命 | 在团队管理中把成员列入某份名单，登录时据此计算岗位角色 |
| 资质名单 | 委员会、产品经理、项目经理、系统工程师四份名单，决定 `IPMT`/`PDM`/`PJM`/`SM` |
| 需求 | 需求识别中登记的功能诉求，可挂接特性 |
| 特性 | 可独立开发、评审、归档的最小功能单元，带版本与 BOM |
| 预立项 | 一个产品版本的前期准备载体，`DRAFT` 至 `CONVERTED` |
| 项目 / 子项目 | 立项产生的研发主体；项目下可分多个子项目，子项目可再分 |
| 根子项 | 立项时自动生成的、与项目同标识的子项目 |
| 工单 | 承载具体工作的任务单，分开发、测试、特性、集成、缺陷处理等类型 |
| 里程碑 | 项目计划中的时间节点，立项时逐特性指定 |
| 评审 | 分特性、子项目、主项目、里程碑、变更五类；除里程碑评审固定按通过处理外，其余四类结论为通过、有条件通过、增补、驳回 |
| 审结 | 汇总委员意见后给出评审结论的动作 |
| CBB | 公共构建块。特性发布为 CBB 后可被后续项目选用 |
| 基线 | 某一时刻的需求、特性、BOM、发布内容的快照 |
| BOM / 物料清单 | 特性或子项目所需的物料集合，评审前须提交并锁定 |
| 料工费 | 材料费、工时费、其他费用三类预算科目 |
| 办理记录 | 单据每一次流转的操作人、时间、动作与意见 |
| 角标 | 侧栏菜单的红点或未读数字，口径见第 3.9 节 |
